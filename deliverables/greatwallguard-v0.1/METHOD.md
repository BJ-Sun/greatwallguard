# GreatWallGuard v0.1 方法说明

## 1. 解决的问题

Agent 的正常执行路径通常不能在任务开始前穷举：工具返回会决定后续工具、参数和状态修改。攻击也可能使用相同工具与相同来源，只在参数、条件、状态版本或后续效果上越权。因此，固定工具白名单会误拦动态任务，单纯的提示注入检测又无法判断一次具体调用是否仍属于用户授权。

GreatWallGuard 将防御形式化为运行时授权证明：

> 当前工具调用是否能由最新可信用户授权、受约束的数据来源和已观测执行事实共同证明？

## 2. 三阶段方法

### 2.1 授权编译

输入为可信用户请求、Agent 能力和工具 schema。受约束的意图编译器生成授权 DAG：

- 终端效果；
- 固定参数和动态参数槽；
- 允许的数据来源与有限变换；
- 条件、对象范围和执行预算；
- 用户明确交给未来邮件、文件或网页的 `DelegationEnvelope`。

DAG 表达允许成立的关系，不预测唯一工具序列。

### 2.2 程序化运行时证明

宿主工具网关记录调用、参数、返回字段、状态版本和真实副作用。证明器使用有限关系完成：

- 参数来源绑定；
- 投影、筛选、聚合和比较；
- 路径、URL、账户和对象范围传播；
- 必要中间能力派生；
- 授权预算消费；
- 持久状态版本可用性检查。

程序证明完整则允许，有限冲突成立则拒绝，缺少关系证据则产生原子证明义务。

### 2.3 证明义务、补证与终局裁决

证明义务把模糊的复核转换成有限问题，例如：

- 这个收件人是否由指定文件字段产生？
- 商品是否满足用户指定的评分条件？
- 当前中间操作是否服务于授权终端效果？
- 外部邮件是否处于用户委托范围？

系统从执行图中切出与问题相关的证据。LLM 只能输出：

- `SUPPORTED`：证据证明当前调用；
- `CONTRADICTED`：存在有限冲突；
- `NEED_EVIDENCE`：指出缺失事实和建议查询。

`NEED_EVIDENCE` 最多触发一次受限 `read/search/inspect_version/replay`。仍未解决时，终局审计输出 `ALLOW/DENY`；策略将仅缺少用户授权依据的情况转为 `CONFIRM`。公开接口没有 `REVIEW`。

## 3. 动态委托

当用户说“查看 Taylor 的邮件并完成他的请求”时，初始授权无法预知邮件中的具体子任务。GreatWallGuard 不把邮件一概视为无权数据，也不让邮件自动获得无限控制权，而是维护：

```text
DelegationEnvelope
├── source selector     指定发件人、文件、URL或对象
├── purpose             用户声明的目的
├── effect classes      允许产生的效果类型
├── max effects         效果预算
├── authentication      来源认证要求
└── confirmation class  必须确认的敏感效果
```

读取匹配来源后，模型可以提出 `AuthorizationDelta`；主机只在来源身份、认证、效果类别和预算全部满足时接受。稳定端点和工具输入—输出能力来自部署环境契约，而不是外部内容。

## 4. 事实图的职责

事实图不判断恶意，只保存可用于证明的事实：

```text
Observation → Action → Effect → State Version
```

它记录调用与参数、工具返回字段、来源、读写对象、持久化版本和因果候选。授权 DAG 表达“允许什么”，执行图表达“发生了什么”，证明义务连接两者。

## 5. 终局语义

| 输出 | 含义 |
|---|---|
| `ALLOW` | 程序或语义证据支持原调用 |
| `DENY` | 明确越界、条件冲突、新增效果或终局高风险未知 |
| `CONFIRM` | 唯一缺口是用户授权或敏感偏好，确认后写回授权状态 |

`CONFIRM` 不是后台人工审核；用户确认应生成授权增量，避免同一事实重复询问。

## 6. 当前最佳结果

完整全量终局结果：

| 数据 | ALLOW | CONFIRM | DENY | REVIEW |
|---|---:|---:|---:|---:|
| 正常任务 157 条 | 126（80.3%） | 14（8.9%） | 17（10.8%） | 0 |
| 有效攻击 1,169 条 | 0 | 25（2.1%） | 1,144（97.9%） | 0 |

正常拒绝归因后的动态委托 pilot 叠加结果：

| 数据 | ALLOW | CONFIRM | DENY | REVIEW |
|---|---:|---:|---:|---:|
| 正常任务 157 条 | 129（82.2%） | 14（8.9%） | 14（8.9%） | 0 |
| 有效攻击 1,169 条 | 0 | 25（2.1%） | 1,144（97.9%） | 0 |

第二张表是机制 pilot 叠加，不是重新在线执行全部 benchmark。14个正常拒绝中约11个轨迹本身存在明确错误或缺证据；人工初步归因的方法误判或策略争议约3/157。

## 7. 已知边界

- 当前结果主要是冻结轨迹上的授权回放，不等同于端到端 ASR/utility；
- 动态委托尚未在两个 benchmark 全量在线重跑；
- 多轮用户 `ADD/MODIFY/REVOKE/SUSPEND` 尚未统一接入主运行时；
- 工具与端点契约仍需要部署环境提供，自动生成尚未完成；
- 真实 Agent 应先使用旁路模式验证，再启用阻断。
