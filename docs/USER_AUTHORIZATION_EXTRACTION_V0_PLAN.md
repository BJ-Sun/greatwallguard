# 用户授权提取 V0：冻结计划

## 唯一实验问题

**只看可信用户消息**，一个自动方法能否逐轮维护当前邮件发送授权，而不把旧要求、含糊续办或资料内容误当成新的发送授权？本轮不读取图、执行轨迹、攻击标签或任务成功 oracle，也不改图。这里的“意图”特指对持久 Effect 的授权，不等同于宽泛的任务目标。

## 从论文借鉴什么，不借鉴什么

- Tack 等的 [Evolving User Intent](https://arxiv.org/html/2607.20734) 将变化明确分为参数补充、参数修订和任务切换。我们借其**可控制的转移类型**设计测试，不使用它的任务最终答案作为安全授权。
- Zhang 等的 [StateForge](https://arxiv.org/html/2609.32520) 把对话折叠成当前有效状态，失效旧值及其依赖推论。我们借其**状态维护方式**，但输出的是可审核的授权，而不是供 Agent 解题的通用记忆摘要。
- [Task Shield](https://aclanthology.org/2025.acl-long.1435/) 已从用户消息提取任务并做行动相关性审查，故“提取用户任务”不是我们可声称的新意。V0 特别测它不能替我们自动决定的授权细节：次数、收件人绑定方式、撤销和不明确的续办。
- [PAuth](https://arxiv.org/html/2603.17170) 提醒未确定运行时参数不能简单当成任意值，也不应默认为已授权；本轮只将其表示为条件槽，不尝试证明实际求值来源。

## 冻结的输入与输出

`experiments/user_authorization_v0/cases.json` 含 7 条短对话，共 12 轮：4 条来自已保存的无注入真实 OpenClaw 任务或正常 stress case，3 条是显式标记的控制探针（改收件人、撤销发送、含糊续办）。后者用于诊断机制，不算真实任务性能。文件逐轮只存用户消息和研究者写的最小参考状态；没有工具轨迹或攻击标签。参考状态仍是**单人研究草稿，不是独立金标**。

每轮只比较同一个简化状态：`send_grants`（一项代表一封可发送邮件，收件人为用户字面值或由指定资料待求值）、`no_send_now`（此刻明确不得发送）、`unresolved_additional_send`（用户话语可能涉及额外发送，但不足以直接扩权），以及 `context_refs`（先前用户指定、供未来授权引用的资料选择器；它**不是授权**）。后者是“先查联系人、下一轮才说发送”所必需，不能把第 1 轮的资料描述误记成发送许可。`send_grants` 是尚未结合执行结果的请求侧承诺；是否已经发送、是否消耗次数不由此实验判断。

## 固定对比和指标

同一 DeepSeek Flash 模型、相同 JSON 输出要求，分别执行：

1. `full_history`：每一轮重读截至该轮的全部用户消息，重新给出当前授权状态。
2. `state_fold`：只看上一轮的授权状态与当前用户消息，更新当前状态。

二者均不得看到参考答案。调用限于上述 12 轮 × 2 方法；单次格式或网络失败记录失败，不按内容结果修改提示词重跑。自动检查 JSON 可解析、发送承诺数量、字面收件人、条件收件人状态、禁发状态和错误扩权；条件资料选择器和含糊续办再逐项人工审查。报告原始分子／分母和具体错误，不写“准确率高”或“安全有效”。

## 实验后如何决定下一步

| 观察到的主要失败 | 后续唯一优先问题 |
| --- | --- |
| 两位研究者对用户话语本身也难以一致标注 | 先收紧授权语义与澄清规则，不换提取模型。 |
| `full_history` 容易保留被改口覆盖的旧授权，`state_fold` 不会 | 继续研究状态转移与撤销；扩大独立多轮正常集。 |
| 两者都错误扩权或漏掉条件槽 | 改授权表示与提取规范，重点测试显式权限与任务相关性的区别。 |
| 请求侧状态稳定 | 再用人工给定的 Effect 测授权比较，最后才接回真实图。 |

本轮 API 只接收这些合成／实验用户消息，不接收原始工作区、工具返回、case 标签或真实凭据。费用与请求数由脚本上限控制。
