# GreatWallGuard：图设计与当前进展

## 一句话概括

GreatWallGuard 先把 Agent 的长程执行过程压缩成可回查的行为图，再在图之上比较“任务允许的行为范围”和“实际产生的持久影响”。图负责记录事实，TaskScope 负责定义正常范围，检测器负责比较两者。

## 1. 图到底记录什么

Agent 的每次执行都统一表示为：

```text
Observation → Action → Effect → State
```

| 节点 | 记录内容 | 典型信息 |
|---|---|---|
| Observation | Agent 接收到的输入、工具返回、文件或记忆读取 | 来源、完整性、对象标识、内容摘要/指纹 |
| Action | Agent 发起的工具调用或后台操作 | 工具、调用 ID、参数摘要、执行决策、执行状态 |
| Effect | 调用实际产生的影响 | 操作类型、目标、是否持久、是否可逆、执行结果 |
| State | 环境中留下的状态版本 | 对象、版本、前后指纹、提交证据 |

基础 Effect 类型保持有限且工具无关：

```text
read | write | create | delete | send | execute | permission_change | unknown
```

图本身不写入“恶意/正常”标签，但保留来源完整性、持久性、可逆性、状态版本和证据等级等安全相关属性。

## 2. 节点和边如何连接

```text
外部返回
   │ derived_from
   ▼
工具调用 Action
   │ causes
   ▼
实际 Effect
   │ updates
   ▼
持久 State 版本
   │ next / reads
   ▼
下一轮读取、规划或工具调用
```

主要关系如下：

| 边 | 含义 |
|---|---|
| `derived_from` | Action 或 Effect 与其输入来源的关联 |
| `causes` | Action 产生了哪个 Effect |
| `updates` | Effect 修改了哪个 State |
| `reads` | 当前行为读取了哪个历史对象或版本 |
| `next` | 执行过程中的时间顺序 |

例如，跨轮攻击会被压缩成：

```text
网页返回 → 写入 MEMORY.md → 再次读取 MEMORY.md → 创建定时任务 → 调度器状态改变
```

其中 `call_id`、参数摘要、来源节点和 State 版本使整条链可以回查到原始 case；图默认不保存隐藏思维过程。

## 3. 四级图视图

同一份事件记录提供四种粒度：

```text
L0  全量审计图：保留观测边界内的事件和证据
L1  规范化过程图：把不同工具归一为 read/write/send 等操作
L2  状态传播图：聚合对象、版本、持久 Effect 和来源链
L3  有界运行时摘要：只保留最近事件、活跃状态和高影响 Effect
```

这样既能离线回放完整过程，又能在长任务运行时控制上下文规模。详细字段和实现见 [图设计说明](GRAPH_DESIGN.md)、[多级图设计](MULTI_LEVEL_GRAPH.md) 和 [图表征规范](REPRESENTATION_SPEC.md)。

## 4. 检测机制与 TaskScope

图不是单独的分类器。检测需要先定义当前任务允许的范围：

```text
用户任务 + Agent 能力 + 工具 schema + 明确授权
                         ↓
                     TaskScope
                         ↓
实际执行 trace → 行为图 → 比较 Effect 是否越界
                         ↓
                  正常 / review / 阻断
```

TaskScope 至少应包含：

```text
允许的工具
允许的目标对象
允许的参数范围
允许的持久副作用
允许的状态变化
```

因此，图回答“实际发生了什么”，TaskScope 回答“当前任务允许什么”。如果 TaskScope 缺失或过窄，正常的 MEMORY.md 写入也可能被误报；如果过宽，攻击行为可能被放过。

## 5. 已完成的验证

我们使用已有的攻击、正常、失败、风险和授权 case 做了离线统一评估，没有重新生成攻击。当前统一评估集包含 534 条样本：305 条双成功攻击、14 条明确授权控制，以及正常任务、失败攻击、仅攻击成功和语义风险对照。

实验流程是：

```text
已有 case 中的任务范围信息 → 构造 TaskScope 代理
完整执行 trace → 生成行为图
TaskScope 与图中的 Effect 比较 → 输出告警
```

这验证的是“给定任务范围时图检测是否有效”，不是 TaskScope 自动生成实验。

结果如下：

| 运行模式 | 结果 |
|---|---:|
| 全量告警/Review 的攻击覆盖 | 305/305 |
| 明确授权控制误报 | 0/14 |
| 高置信阻断的攻击召回 | 84.6% |
| 高置信阻断在正常任务上的误阻断 | 15.3% |

全量模式保留更多可疑证据，适合审计；高置信模式只阻断不可逆操作、参数明显偏离或不可信来源驱动的持久影响，普通状态写入先进入 Review。

## 6. 当前结论和问题

验证说明：

1. 行为图能够稳定记录跨轮工具调用、持久化写入和状态传播；
2. 攻击成功通常会留下可观察的 Effect，因此图可以作为长程检测的证据层；
3. 图检测的主要瓶颈已经从“能否记录行为”转为“能否准确生成任务允许范围”。

当前仍存在两个关键问题：

- 现有 TaskScope 主要来自 case 中已有的 `utility_oracle_calls`、`intended_tool_calls` 或合成任务字段，并非系统自动生成；
- 持久化内容和模型输出目前主要以摘要、指纹和过程证据表示，尚未充分表达“正常记录”与“行为指令/输出偏移”的语义差异。

## 7. 下一步推进

下一阶段拆成两个独立实验：

1. **TaskScope 生成实验**：只使用攻击注入前的正常任务、Agent 能力和工具 schema，预先生成并冻结允许范围；
2. **固定 Scope 的图检测实验**：在不读取攻击结果或攻击目标的条件下，用冻结 Scope 比较正常、攻击、失败和授权 case。

同时补充持久化内容摘要、输出偏移和字段级来源证据，最终分别报告 Scope 生成质量、攻击召回率、正常任务误报率、最早检测轮次和图压缩率。
