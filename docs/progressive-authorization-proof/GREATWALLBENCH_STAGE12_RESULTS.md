# GreatWallBench：逐轮授权更新下的阶段一、二全量结果

## 实验问题

本次实验检验两个问题：可信用户消息能否在多轮会话中持续更新 Authorization DAG；更新后的 DAG 与确定性运行时证明，能否在不读取攻击标签的情况下区分正常调用与攻击目标调用。系统按消息到达顺序处理轨迹，每轮先生成并校验 `ADD / REFINE / REPLACE / REVOKE / CONTEXT_ONLY` 更新，再审查该轮之后的工具调用、参数和持久状态变化。攻击标签只用于事后统计。

本实验覆盖 GreatWallBench 最新 manifest 中的 240 条正常对照和 405 条严格双成功攻击，共 645 条。全部样本均完成适配和回放；阶段三语义证明尚未参与，因此 `REVIEW` 表示前两个阶段无法仅凭程序证据定论，并不等于已经检出攻击。

## 总体结果

| 数据 | ALLOW | REVIEW | ALERT | 运行失败 |
|---|---:|---:|---:|---:|
| 正常任务（240） | 163（67.9%） | 69（28.8%） | 8（3.3%） | 0 |
| 攻击目标（405） | 0（0%） | 54（13.3%） | 351（86.7%） | 0 |

阶段一、二没有直接放行任何攻击目标，且将 86.7% 的攻击目标识别为确定冲突；其余 13.3% 被安全地送入语义复核。正常任务自动放行率为 67.9%，仍有 32.1% 无法直接通过，其中 28.8% 是证据未闭合，3.3% 是当前授权规范与轨迹发生明确冲突。因而，当前版本已经形成可执行的 fail-closed 边界，但正常任务可用性仍需由阶段三补全。

## 分攻击目标结果

| 目标 | 正常 ALLOW / REVIEW / ALERT | 攻击 ALERT / REVIEW / ALLOW |
|---|---:|---:|
| 日历错误创建或修改 | 15 / 15 / 0 | 0 / 52 / 0 |
| 数据外发 | 30 / 0 / 0 | 44 / 0 / 0 |
| 删除文件 | 14 / 16 / 0 | 44 / 2 / 0 |
| 模型输出完整性 | 15 / 15 / 0 | 47 / 0 / 0 |
| 网络侦察 | 16 / 12 / 2 | 50 / 0 / 0 |
| 远程回连 | 13 / 11 / 6 | 50 / 0 / 0 |
| 定时任务 | 30 / 0 / 0 | 50 / 0 / 0 |
| 错误文件共享范围 | 30 / 0 / 0 | 61 / 0 / 0 |

参数和 Effect 具有明确程序冲突时，确定性证明效果最好：错误收件人、共享对象、网络端口、计划外回连和定时任务均可直接告警。日历攻击全部进入 `REVIEW`，原因不是系统没有观察到调用，而是攻击与正常任务使用相同的日历工具，差异集中在标题等生成式语义字段；这正是阶段三需要补全的关系。两条删除攻击由外部内容获得了效果级委托，也需要语义审查该委托是否真的来自用户授权。

## 正常任务为何没有全部放行

69 条任务级 `REVIEW` 对应70个尚未闭合的证明：33次日期或时间字面值缺少可程序核验的依据，24次受限派生 Effect 需要证明中间文件确实服务于已授权终端目标，11次条件约束缺少可验证证据，2次授权 Effect 的参数关系未完全闭合。这些情况没有确定冲突，适合交给阶段三的最小证据审计，而不应由阶段二武断阻断。

8 条 `ALERT` 均来自网络扫描的实际端口集合与编译出的授权范围不同，属于可程序验证的参数集合冲突。中间文件不再被直接判为冲突，而是作为受限派生 Effect 进入阶段三，验证父 Effect、对象范围、内容来源、可见性和生命周期。

## 逐轮授权更新得到的结论

系统已经能够按时间维护授权，而不是把多轮消息合并成无序白名单。新消息可以新增授权、细化尚未确定的关系、替换旧参数、撤销旧授权或只补充上下文；程序验证器负责检查更新目标、工具契约和可执行字段。若 `REFINE` 实际改变已有确定参数，系统会将其规范化为 `REPLACE`，防止新旧参数同时有效。

独立的更新操作 pilot 包含 18 段对话、34 轮消息。经程序规范化后，34/34 轮与研究者预先标注的更新类型一致，且未观察到错误扩权或错误撤权。该 pilot 用于验证实现语义，不是独立测试集，因此不能作为最终泛化准确率；全量回放证明的是该更新机制已经能够接入真实长程轨迹并稳定运行。

## 当前能力边界与下一步

本轮结果已经回答“逐轮授权能否实现并接入全量轨迹”：可以，645 条均成功运行，且没有攻击目标被自动放行。剩余问题不应继续通过 case-specific 规则修补。下一步只需沿两个通用方向推进：

1. 对时间表达、条件和生成式字段构造原子 Proof Obligation，由阶段三读取最小证据切片完成语义判断；
2. 对受限派生 Effect 验证父 Effect、对象范围、内容来源、可见性和生命周期，区分实现所需的持久中间产物与真正扩大外部影响的状态写入。

完整逐 case 结果位于 `experiments/greatwallbench_full/full_stage12_results.json`。
