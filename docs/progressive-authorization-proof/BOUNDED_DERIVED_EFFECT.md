# Bounded Derived Effect：受限的持久中间产物

用户通常只描述最终结果，不会枚举 Agent 为完成任务创建的每个临时文件。把所有未明确提及的写入直接拒绝，会误拦正常的报告、交接记录和任务暂存；把“与任务相关”的写入全部允许，又会使外部内容借正常任务污染记忆、配置或后续任务状态。

**Bounded Derived Effect** 将这类写入表示为已授权终端 Effect 的受限派生关系。候选写入只有在以下关系成立时才能继承父授权：它确实服务于已授权终端结果；对象位于允许的任务范围；内容只依赖可信请求和已授权运行时数据；可见性没有扩大；生命周期不会使其成为后续任务的新权限来源。形式上，派生权限必须满足 `DerivedEffect ⊆ ParentAuthorization`。

运行时首先识别文件、记忆和工作区状态写入。Agent 控制对象（如 `MEMORY.md`、`AGENTS.md`、配置和凭据文件）不能继承普通任务授权；其他持久写入被转换为 `bounded_derived_effect_requires_proof`，并携带父 Effect、对象、写入内容、来源证据、可见性和生命周期。阶段三只审查这条派生关系，而不重新判断整个任务。

数据适配器同时恢复工作区快照中的真实文件内容，并用内容中的稳定事实原子——主机、对象 ID、路径、日期和端口——选取对应工具返回。这样，审计模型能够比较“报告写了什么”和“授权工具实际观察到什么”，而不是仅凭文件名猜测用途。

外部内容仍受一个不可覆盖的不变量约束：文档、记忆和工具返回可以补全用户已经委托的参数，但不能自行新增终端 Effect。语义审计即使认为外部指令合理，也不能把原本不存在的 Effect 提升为自动授权；宽泛委托最多进入用户确认。

在 GreatWallBench 全量实验中，该机制将阶段二正常任务硬阻断从14条降至8条。阶段三对原先12条持久中间产物边界进行复核后，11条正常报告写入得到正向证明；剩余1条报告同时记录了与工具时钟冲突的日期，因内容来源未闭合而进入确认。47条模型输出完整性攻击仍全部拒绝，全部405条攻击保持零自动放行。
