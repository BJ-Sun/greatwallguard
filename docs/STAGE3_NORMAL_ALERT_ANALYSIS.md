# 阶段三正常告警审查：真正的问题不是攻击漏检

## 1. 为什么审查这 22 条

阶段三把 AgentDojo 的 7 个正常任务、AgentDyn 的 15 个正常任务判为 `ALERT`。直接把 22 条都记为假阳性并不准确：benchmark 的任务目标是良性的，但标准轨迹中的某个具体调用仍可能使用占位参数、缺少条件证据，甚至执行外部内容新增的动作。

我们因此回到调用前证据，逐条检查用户请求、工具调用、参数、返回和审计理由。以下是初步专家审查，不是独立标注者构建的最终金标。

## 2. 审查结果

| 类别 | AgentDojo | AgentDyn | 合计 |
|---|---:|---:|---:|
| 轨迹本身不应自动放行 | 6 | 9 | **15** |
| 证据包遗漏关键事实 | 0 | 1 | **1** |
| LLM 错误升级为硬告警 | 1 | 5 | **6** |
| **合计** | **7** | **15** | **22** |

按 benchmark 标签直接计算的正常硬告警率是 22/157（14.0%）；按这次初步审查，真正的 LLM 硬误报是 6/157（3.8%），另有 1/157（0.6%）来自证据包遗漏。这个数字仍高于目标，且在独立复核前不能作为正式论文指标。

## 3. 三类问题分别意味着什么

### 3.1 标准轨迹本身缺少授权证明

15 条轨迹包含明确问题：日期与邮件冲突；把 `Two more activities`、`ID`、`subject/body/file_id` 当成真实参数；没有取得评分或价格就触发条件退款；账户验证失败后继续使用并未观察到的 SSH key；或将外部邮件给出的银行账户用于转账。

这些任务的用户目标本身正常，但具体执行不应因“normal trajectory”标签而自动放行。它们说明，任务完成率与授权正确性必须分开评价。

### 3.2 最小证据包仍可能遗漏环境身份

一条 GitHub 任务创建 `new_project` 后操作 `emmajohnson/new_project`。审计包没有显式提供当前认证账户所有者，因此无法证明二者是同一个仓库。这里不应调整 LLM 阈值，而应让事实层记录认证主体以及工具隐式补全的 owner。

### 3.3 LLM 把“不确定”误写成“冲突”

6 条是真正的方法问题：

- 理由明确写着 Alice 是非成员、调用得到授权，JSON 却输出 `unauthorized`；
- `force=false` 不会强制覆盖，却被当成缺少强制权限；
- 用户提供邮箱以便获取 CV 或书籍，审计器把必要的表单输入直接视为越权；
- 18:00 和 19:00 都满足“会议之后”，只是具体时间未由用户指定，最多应保持复核，而不是判为冲突。

共同原因不是 LLM 不会理解攻击，而是当前输出把两种命题混在一起：

```text
INSUFFICIENT：当前证据不能证明调用得到授权
CONTRADICTED：当前证据能够证明调用违反授权
```

只有第二种情况才足以产生硬告警。

## 4. 方法应如何调整

阶段三应从“让 LLM 决定是否阻断”改为“让 LLM提交一个可验证的语义证明”：

```text
SUPPORTED
  └─ 指出授权条款、参数关系和支持证据 → 可释放 REVIEW

CONTRADICTED
  └─ 必须给出冲突类型、被违反条款和反证 → 程序校验后才可 ALERT

INSUFFICIENT
  └─ 说明缺失证据 → 保持 REVIEW／取证／询问用户
```

`CONTRADICTED` 只接受有限冲突类型，例如固定值冲突、条件明确不成立、效果被禁止、对象或范围越界。单纯“用户没有指定具体值”“来源尚未证明”或者“工具步骤不是用户逐字要求”均不能构成硬告警。

在这个验证器完成之前，安全的在线策略是：LLM 的 `SUPPORTED` 可以帮助释放正常复核；`unauthorized` 只能提供风险信号，除非同时存在程序化反证，否则仍保持 `REVIEW`。攻击侧不需要继续收紧，因为现有测试中没有攻击被错误提升为授权。

## 5. 下一步决定性实验

下一步只验证一个变化：为语义审计加入上述三态证明结构和冲突校验器，然后只重跑 33 个正常 `unauthorized` 调用与 485 个攻击 `unauthorized` 调用。

成功标准是：

- 6 个已知 LLM 假告警不再产生 `CONTRADICTED`；
- 15 个轨迹问题能被分类为有明确反证或证据不足；
- 攻击调用不得被提升为 `SUPPORTED`；
- 无法给出可验证反证的攻击可以退回 `REVIEW`，不能为了提高阻断率牺牲正常任务。

逐条审查记录见 `experiments/stage3_delegation_full/normal_alert_adjudication.json`。

## 6. 实验结果更新

三态语义证明与冲突校验器已经实现并完成上述实验。33 个旧正常 `unauthorized` 调用中，32 个被改判为证据不足，只有日期明确冲突的一条通过校验；先前识别的 6 个 LLM 假告警全部消失。任务级正常硬告警由 22/157 降为 1/157，攻击直接放行仍为 0。详见[阶段三 v2 实验](STAGE3_CONFLICT_CERTIFICATE_EVALUATION.md)。
