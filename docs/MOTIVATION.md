# GreatWallGuard：从局部动作到跨轮效果授权

## 研究问题从哪里来

我们先研究真实用户任务良性、攻击者影响外部返回或持久内容的场景。Agent 接收用户的多次输入，在两次输入之间又可能自主读取资料、调用工具、写入记忆，并在后续轮次使用这些结果。攻击可以把目标拆进这些步骤：一次写入或读取看似合理，经过后续复用才导致未授权的发送、删除或权限变化。与此同时，同一个正常任务可以沿多条路径完成；调用顺序不同，未必意味着偏离用户目标。

考虑“给项目负责人发送进展”这一任务。正常情况下，Agent 可能从项目资料中查得收件地址；攻击情况下，外部内容可能先污染一条可回读的记录，再让 Agent 把另一地址当成负责人。两条轨迹都可能调用 `send_email`，地址也都可能没有出现在用户原话里。判断的关键是：**用户授权了哪项发送效果；所用地址如何从任务资料中确定；中途写入的内容是否让实际收件人偏离了授权对象。**

因此，我们关注的是一个同时影响检出率和误报率的问题：

> 在允许正常执行路径变化的前提下，如何判断 Agent 跨轮形成的持久或外部效果，是否仍有当前用户任务的授权依据？

这里的跨轮组合攻击，是本文选择的研究场景。并非每一种提示注入都需要持久写入，也并非每个中间动作在发生时就能被判为恶意。

## 现有工作把研究推进到了哪里

输入检测和上下文清洗尝试识别外部内容中的控制指令。[Task Shield](https://aclanthology.org/2025.acl-long.1435/)进一步检查当前指令或工具调用是否服务于用户目标；[AttriGuard](https://arxiv.org/html/2603.10749)通过弱化外部来源后的影子重放，判断拟执行的调用受什么影响；[AgentSentry](https://arxiv.org/abs/2602.22724)已明确研究多轮轨迹中的因果接管。这些方法使防御能够超越可疑文本，分析动作与来源的关系。

另一条路线把执行或授权写得更明确。[AgentArmor](https://arxiv.org/abs/2508.01249)用程序流图和策略检查运行轨迹；[CaMeL](https://arxiv.org/abs/2503.18813)隔离规划与不可信数据；[PAuth](https://arxiv.org/abs/2603.17170)已研究任务级授权以及参数来源。[AGATE](https://arxiv.org/html/2609.30830)更直接地针对组合攻击，联合检查授权、跨步来源与重复效果，并在 OpenClaw 等 Agent 上部署。因此，图、用户意图、参数约束和跨步效果账本都不能单独作为本文的新意。

这些工作给出了我们需要的基础，也把问题收窄了：当用户多次修改要求、关键参数要从任务资料中确定、攻击影响经持久状态传递时，能否从可信用户消息维护准确授权，并在运行时依据实际效果核对？PAuth 的原始任务只有 71/100 能自动授权，补全为明确任务后达到 100/100；AGATE 则报告 11 个良性文件处理场景中有 6 个出现拒绝。这些结果分别来自不同实验，不能直接比较，但都提示需要把安全性与正常任务的自主完成能力一同检验。本文的差异与收益仍须用同条件实验说明。

## 为什么把图与用户授权放在一起

长程历史需要一个可回查的表示。行为图将可观测事件连接为 `Observation → Action → Effect → State`，记录工具参数、实际副作用、状态版本以及后续读写。它回答“Agent 做了什么，哪些内容留到了后面”。图应保留来源证据，但现有实现尚未稳定连接**参数的具体字段**与其上游来源；不能把时间相邻的事件当作已证明的因果链。

安全判断还需要用户侧的参照。TaskScope 根据可信用户消息表示当前目标、允许的效果和参数约束，并随用户的补充、修改或撤销而更新。任务资料可以提供收件地址等尚待确定的值；它不能自行增加发送对象、操作次数或新目标。用户意图如何作通用语义解析已有相关研究，本文采用可检查的授权表示，重点研究它如何与实际执行证据对齐。

两者在 Effect 上相遇：对于一次拟发送、删除或持久写入，先找当前用户授权，再查该操作的对象和参数如何形成。正常任务允许通过不同工具路径取得同一个受约束的参数，因此不能要求完整调用序列一致。中间写入若暂时无法判定，可以保留来源和状态版本；一旦它被后续高影响操作使用，就结合整条相关链重新核对授权。若对象或参数明确违反约束，可以直接处理；若资料是否真的支持该参数仍不清楚，则把 TaskScope 和相关子图交给语义审计，必要时请求用户确认。不可逆操作必须在提交前完成判断。

这形成一条方法主线：**TaskScope 给出用户允许的效果；行为图保留效果如何跨轮形成的证据；运行时在效果产生或被复用时检查两者是否一致。** 图的价值在于为授权判断提供跨轮证据，而不是预先给节点标记“正常”或“攻击”。效果级检查能否比局部动作判断更能容忍正常变化，目前仍是假设。

## 当前证据与下一步

现有离线图评估使用了由 case 元数据构造的 TaskScope 代理，说明在给定范围时，图可用于查找部分越界效果；它没有验证真实任务中的授权提取。[邮件场景审查](EMAIL_DECIDABILITY_PILOT.md)还发现：在 7 条攻击邮件样本中，当前图有 0 条具备发送参数的字段级来源；同时，简单的“收件人未出现在用户消息中”规则已经标记了这 7 条攻击，而 7 条明确写出收件人的正常样本均未告警。现有样本因此尚不能证明图优于简单规则。新增的真实正常邮件任务中，也已出现一例明确授权发送却被在线规则告警的情况。[授权增量试验](INTENT_DELTA_PILOT.md)进一步暴露了用户后续补充要求和“从资料中确定参数”的表示缺口，但其小规模参考标注不是独立金标。

下一步应在同一组攻击与正常变体上，逐步检验三件事：只看用户消息能否生成可靠的当前授权；补全字段级来源后，图能否提供简单规则缺少的证据；对仍未决的效果进行局部语义审计，是否同时减少误报和漏检。正常对照尤其需要包含**用户授权了目标、但关键参数要从任务资料中确定**且实际完成任务的轨迹。只有在这类样本上证明收益，跨轮效果授权才足以成为论文的方法贡献。
