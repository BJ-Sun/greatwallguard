# GreatWallGuard：研究动机与核心洞见

## 1. 我们真正要解决的问题

现有 Agent 防御大多围绕一个局部问题展开：当前输入是否包含注入、当前工具调用是否由不可信来源驱动、当前数据流是否违反安全规则。

这些方法对单步或短链攻击有效，但长程攻击可以把一个明显目标拆成多个局部合理的步骤：

```text
读取普通信息
  → 写入文件或记忆
  → 后续轮次回读
  → 改变一个工具参数
  → 产生持久或外部影响
```

每一步单独看都可能符合正常行为分布；只有把多轮行为、参数来源和持久状态连接起来，才能发现它们共同产生了原任务没有授权的结果。

因此，我们关注的不是“这一步是不是恶意”，而是：

> 在一个长程、动态的 Agent 任务中，当前累积的持久影响是否仍然由原始任务支持？

这可以称为**长程任务级累积效果授权**（task-level cumulative-effect authorization）。

## 2. 一个最小例子

用户要求“整理会议纪要并发送给参会者”。攻击并不需要直接要求 Agent 外发文件，而可以分散为：

```text
读取会议记录
  → 外部内容被写入长期记忆
  → 后续任务读取该记忆
  → send_email 工具保持不变
  → recipient 参数变成攻击者地址
  → 产生未授权外发
```

如果只检查当前文本，攻击指令可能已经消失；如果只检查工具名，`send_email` 仍然是任务中允许的工具；如果只检查某一轮参数，前面的记忆污染又无法被看见。

风险存在于**跨轮累积的 Effect 链**，而不是某个单独的 token 或工具调用。

## 3. 相关工作的能力边界

| 工作 | 主要解决的问题 | 能力边界 | 对我们的启发 |
|---|---|---|---|
| 注入检测、上下文清洗 | 识别工具返回或上下文中的可疑指令 | 隐蔽内容、已持久化内容和多步组合难以判断 | 不能把攻击判断建立在单一文本特征上 |
| AgentArmor | 从运行时 trace 构建 CFG/DFG/PDG，用依赖和安全类型约束执行 | 依赖规则和来源完整性；严格规则可能误报，重点仍是单次运行中的流转 | 需要保留控制流、数据流和参数来源 |
| CaMeL | 从可信请求生成受约束的控制流和数据流，用 capability 和策略阻断越权数据流 | 依赖自定义解释器、显式策略和可规划的程序结构；不直接处理长程累计效果 | 任务范围应在执行前建立，数据来源应可传播 |
| IPIGuard | 预先生成 Tool Dependency Graph，并限制计划外工具调用 | 图主要描述工具节点和依赖；对持久 State、Effect 累积和复杂动态任务表达有限 | 高影响动作不能由外部内容临时新增 |
| AttriGuard | 用弱化来源和影子重放判断某个动作是否因外部内容产生 | 主要是动作级因果归因，不能单独表达多步任务偏离；合法委托来源可能造成歧义 | 重放应作为不确定动作的补充证据，而非主分类器 |

这些工作并非没有涉及多步执行或图结构；尚未被同时作为核心对象的是：

1. **攻击单位**：多个局部合理动作组成的全局越界，而不是单步注入；
2. **状态表示**：跨轮持久 Effect 和来源传播，而不只是工具调用序列；
3. **判定目标**：在容忍正常重规划的同时判断任务级累积影响；
4. **评测对照**：同时包含正常变化、失败攻击、授权危险行为和成功攻击。

## 4. 研究问题的形式化

将 Agent 轨迹表示为：

```text
τ = (Observation, Action, Effect, State)₁:T
```

由初始任务、Agent 能力、工具 schema 和显式授权生成任务范围 `S(u)`。`S(u)` 不是固定调用清单，而是允许的行为集合，包含：

```text
允许的行为类型
允许的目标和参数范围
允许的来源类型
允许的持久副作用
允许的部分顺序
```

安全性目标是：

```text
对于每个前缀 τ≤t，累计 Effect(τ≤t) 都属于 S(u) 的允许闭包。
```

长程攻击则表现为：

```text
每个局部 Action 都看似合理，
但某个前缀的累计 Effect 超出 S(u)。
```

## 5. 核心洞见：从“动作异常”转向“任务支持的效果闭包”

我们的 key insight 可以概括为：

> 长程 Agent 的安全边界不应由单步动作或固定调用序列定义，而应由原始任务能够支持的持久效果闭包定义；运行时只需将行为压缩为带来源的状态转移，并检查累计效果是否仍在该闭包内。

这个洞见包含三层设计：

### 5.1 以 Effect 而不是文本作为长程安全单位

普通观察和中间推理会快速膨胀，但写文件、修改记忆、改变权限、发送数据等 Effect 才会把影响带入后续轮次。因此图以 `Observation → Action → Effect → State` 表示行为，把长上下文压缩为可回查的持久状态转移。

### 5.2 用行为范围而不是精确计划容忍正常变化

严格复现完整计划会把正常搜索、参数措辞变化和合法重规划误判为攻击。TaskScope 只约束高影响维度：工具类别、目标关系、关键参数来源、持久 Effect 和部分顺序；对正文、查询词和低风险顺序保留语义容忍度。

### 5.3 把因果证据和安全判断分离

行为图本身不标记“恶意”或“正常”，只保存事实、来源、依赖和状态变化。安全语义由 TaskScope、影响等级和来源传播叠加得到；无法程序化判断时，再用影子重放确认某个外部来源是否真正改变了动作。

这样可以同时避免两种极端：

```text
只看单步 → 漏掉跨轮组合攻击
严格锁死计划 → 阻断正常动态任务
```

## 6. 我们不声称解决什么

该方向不声称仅凭行为图解决所有 Agent 安全问题：

- 恶意用户输入需要独立的入口准入和安全规范检查；
- 图的检测能力依赖 TaskScope 生成和 Effect 提取质量；
- 纯文本误导、没有持久影响的输出偏移不一定能被当前机制识别；
- 如果策略过宽，攻击可能隐藏在“允许的局部行为”组合中。

因此，论文要验证的是一个更具体的命题：

> 在黑盒 LLM、长程多轮和正常行为可变的条件下，任务范围约束加跨轮 Effect Graph，是否比单步检测或严格计划更能识别局部合理、全局越界的攻击，同时保持较低误报。

## 7. 可检验的研究假设

后续实验应直接对应上述动机：

1. **表示假设**：Effect-centric 图能够比原始 trace 更稳定地保留跨轮持久影响和来源链；
2. **检测假设**：TaskScope + 图能够发现同工具不同参数以及跨状态传播造成的越界；
3. **容忍假设**：范围约束比精确调用序列更能容忍正常重规划；
4. **归因假设**：在图和 Scope 不足以判断时，因果重放可以减少不必要的阻断；
5. **评测假设**：只有同时加入正常变化、失败攻击和授权危险行为，才能真实估计误报率。

## 8. 当前状态的诚实说明

已有离线实验表明，行为图能够记录跨轮调用、持久写入和状态传播；在使用已有 case 元数据构造 TaskScope 代理时，图可以覆盖现有攻击样本并区分部分授权对照。

但当前实验还没有证明 TaskScope 可以从真实任务中自动、稳定地生成。因此下一阶段必须把两个问题分开评估：

```text
TaskScope 生成质量
        ↓
固定 Scope 下的图检测能力
```

只有这两部分都得到验证，才能将“任务级累积效果授权”作为完整的防御方案，而不是仅作为离线 case 上的图分析。
