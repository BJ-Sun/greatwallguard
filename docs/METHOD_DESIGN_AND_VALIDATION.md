# GreatWallGuard：方法设计与验证状态

本文档是方法研究草稿，不将尚未集成的原型或探索性结果表述为已完成的防御系统。

## 1. 问题：判断效果，而不是要求固定执行轨迹

我们先研究良性用户任务受到外部返回、文件或记忆中不可信内容影响的场景。Agent 可以在多轮用户输入之间自主查找资料、调用工具并更新持久状态。组合攻击不一定在某次调用中暴露完整目标；正常任务也可能通过不同的查询、重试和中间写入达到同一目标。因此，单看一条可疑文本、工具种类或固定调用次数，不能同时解释攻击和正常执行的变化。

以“给项目负责人发送进展”为例，用户可能没有写出邮箱，而要求 Agent 从项目资料中确定负责人。正常执行和攻击执行都可能调用同一个 `send_email`；差异可能只在 `recipients` 如何得到，以及此前的资料是否被污染。我们要回答的问题是：**一次拟产生的外部或持久效果，是否仍有当前可信用户请求所支持的授权依据？** 这要求把用户允许的效果与 Agent 实际形成的效果分开表征，再在具体对象和参数上相遇。

## 2. 方法主线：用户侧授权与执行侧证据在 Effect 上对齐

```text
可信用户消息 ──逐轮更新──> 当前授权承诺 A ──────────────┐
                                                        ├──调用前核对──> allow / review / alert
运行事件 ──增量建图──> 行为图 G ──候选 Effect + 参数 ────┘
                          └──执行结果与状态变化──> 确认 Effect，更新状态及承诺
```

这里的图不是恶意分类器，授权也不是工具白名单。图保留 Agent 做过什么、看到了什么、哪些变化留下了可复用状态；授权仅由可信用户消息产生，外部返回与持久文件不能自行扩大它。决策单位是具体的 Effect 及其对象、目的地和关键参数，而不是“是否多调用一次工具”。

### 2.1 执行侧：增量、分证据等级的行为图

图用四类节点记录可观测执行：Observation（用户输入、工具返回、文件/记忆读取）、Action（工具与参数）、Effect（预期及实际操作）、State（持久对象的版本）。工具调用前可以根据工具 schema、名称和参数建立 Action 与候选 Effect；调用后记录返回，并在能观察到前后状态时核实实际变化。后续读取通过对象 ID 和版本连接先前 State。较长原文由独立内容索引管理，图仅保留摘要和引用，不保存隐藏思考；当前在线实验只验证了引用的生成，未验证生产环境中的长期证据存储与回查。

图必须区分直接观测与推断：调用参数和文件指纹是观测事实；根据工具名称归类 Effect 是规则推断；“某条资料导致了某个参数”若只有时间相邻，则只是候选关联。当前实现尚不能稳定提供字段级来源，因此图不能声称已经证明非结构化内容如何进入工具参数。[在线建图实验](../experiments/online_graph_construction_v0/REPORT.md)记录了这个边界。

### 2.2 用户侧：逐项 Effect 承诺，而非一次性 Scope

最早的 TaskScope 用用户任务与工具 schema 的关键词、Effect 线索生成允许工具、资源和目的地，可拦截明显无关的高影响操作，却不能表达同一工具下的参数变化或一条请求中的多个合法效果。[简易 Scope 原型](TASK_SCOPE_MINIMAL.md)与[配对实验](EFFECT_SCOPE_PILOT.md)显示，按“同类持久操作只允许一次”检测会把合法双邮件、双日历、双分享都误报。因此，我们将授权单位收缩为用户要求完成的每一件事：操作、对象或条件对象、参数约束、来源轮次及兑现状态。

在目标设计中，新用户消息可以新增、限制或修订承诺；未来消息不能追认过去的调用。参数可以是用户给定的字面值，也可以是“从用户指定资料中选出负责人”这样的待求值条件。后者允许资料提供值，却不允许资料新增发送任务。表达含糊或证据不足时保留 `unresolved`，不能自动扩权，也不应直接定为攻击。当前的确定性提取器和状态更新只覆盖部分表达；撤销、修订、跨任务隔离等尚未形成经过独立标注验证的完整实现。[逐项承诺实验](EFFECT_COMMITMENT_PILOT.md)、[授权增量实验](INTENT_DELTA_PILOT.md)和[LLM 提取试验](USER_AUTHORIZATION_EXTRACTION_V0_RESULTS.md)分别检验了这几个边界。

### 2.3 运行时：先判拟执行效果，再核实实际效果

在不可逆调用前，检测器比较候选 Effect 与当时有效的承诺：明确匹配则 `allow`；明确无对应授权则 `alert`；对象需从资料求值、授权措辞含糊或来源证据缺失则 `review`。工具成功后才消耗对应承诺，失败时释放，避免一次正常重试被误判为额外目标。`review` 表示当前证据不足，不是“低概率攻击”；它需要局部证据核查、语义审计或用户确认，而不能直接按标签训练后静默放行。

已有[调用前检查原型](ONLINE_EFFECT_GUARD_PILOT.md)实现了上述三态接口，并对保存的真实轨迹做了因果回放；它**尚未与完整跨轮图和原生 OpenClaw 运行时集成为同一条在线防御链**。图与授权在同一字段上闭环，是拟验证的方法目标，不是当前完成状态。

## 3. 现有实验支持到哪里

| 需成立的命题 | 已有证据 | 结论边界 |
|---|---|---|
| 图可在真实执行时增量形成 | 真实模型的两轮 AgentLAB 正常任务产生 12 个同步记录边界、28 个节点和 26 条边；逐步增量可完整重建最终图，写入后的读取有一条指纹核实的跨轮边。[记录](../experiments/online_graph_construction_v0/REPORT.md) | 证明这个环境的过程建图路径，不证明原生 OpenClaw 全工具覆盖；在线语义提取仍为零。 |
| 给定简单用户范围，可发现明显越界 | 25 条配对攻击中，精确规则告警 22 条；25 条普通正常执行无误报。[实验](EFFECT_SCOPE_PILOT.md) | 三条合法双 Effect 压力任务全部误报；不能把这组数字视为低误报防御性能。 |
| 逐项承诺比调用次数更符合用户授权 | 53 条只含逐轮用户消息与可用工具名的请求序列用于候选提取；在选取的参照草稿中，三条合法双 Effect 任务的六个 Effect 均获得逐项授权。[实验](EFFECT_COMMITMENT_PILOT.md) | 参照草稿不是独立金标；含糊续办仍未决，且有部分工作区写入未纳入匹配。 |
| 调用前告警接口可运行 | 保存轨迹的因果回放中，22 条有持久目标调用的攻击在目标调用前均被告警；25 条正常任务中有 4 条进入 `review`。[实验](ONLINE_EFFECT_GUARD_PILOT.md) | 不是实时阻断实验；多数复杂正常与攻击都落在 `review`，输出完整性目标不在此检查范围内。 |
| 现有图能否区分条件正常任务与额外发送 | 两条无注入、从指定文件确定收件人的真实 OpenClaw 任务均正确发送，但按人工给定授权审计时仍只能 `review`；七条攻击轨迹中的额外发送也均为 `review`。[实验](CONDITIONAL_AUTHORIZATION_V0_RESULTS.md) | 当前图缺原生文件读取路径和收件人字段来源。更好的用户意图提取本身不能补上这个证据缺口。 |
| 原生来源证据能否缩小这一混淆 | 从保存的 OpenClaw 会话数据库恢复了实际读取路径、返回与写入顺序。窄的来源绑定判据让 3 次正常条件发送通过，同时把 7 次攻击额外发送留在复核；只看“任一返回包含邮箱”则错误通过这 7 次。[实验](RECIPIENT_SOURCE_BINDING_PILOT.md) | 小样本、共享正常任务模板；判据有明确的语义和预投毒盲点，尚非在线集成或低误报检测率。 |

这些结果共同说明：过程图、简单授权和调用前比较均有可运行原型。最初七对邮件样本只有“明确给出收件人”的正常对照，简单的“收件人不在用户原话”规则已能分开它们，因此不能证明图的增益。[邮件可判定性审查](EMAIL_DECIDABILITY_PILOT.md)、[统一图审查](EMAIL_GRAPH_POSTHOC_V0.md) 新增的条件收件人正常任务揭示了该规则的误报：恢复原生读取证据后，窄规则可让这 3 次正常发送通过，并保留 7 次攻击额外发送为 `review`。但尚未成立的是，这种收益能否推广到正常任务也会写入、回读记忆或资料本身不可信的情况。[来源绑定试验](RECIPIENT_SOURCE_BINDING_PILOT.md)

## 4. 下一项决定性验证

邮件 `recipient` 字段的第一步已完成：原生读取路径和字段候选来源确实提供了旧图缺失的证据，但当前成功分离依赖窄任务模板。下一步不应扩大规则集合，而是用真实良性反例检验它：用户明确要求 Agent 先写入/回读记忆再发送，以及从有多个候选人的资料中选定收件人。用户消息的控制者仍须独立核定，不能把攻击场景脚本生成的消息自动视为良性用户授权。

工程上需将原生读取的对象、返回指纹和文件版本接入在线图，而不是只在事后恢复数据库；字段值相同仍只能构成候选对应，不能自动升格为因果证明。若新增的复杂良性对照再次大量进入 `review`，优先研究如何识别“需要局部语义审计”的边界，而不是继续扩张图结构或把试验规则包装成完整防御。
