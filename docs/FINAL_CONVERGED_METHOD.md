# GreatWallGuard：当前收敛方法

## 1. 方法要解决什么问题

动态 Agent 的正常工具序列和参数往往无法在执行前穷举；攻击也可以使用相同工具和相同来源，只改变参数、条件或后续效果。因此，单纯匹配工具白名单会误报，直接把长轨迹交给 LLM 又容易把证据不足误判为攻击。

GreatWallGuard 将防御改写为一个运行时证明问题：**用户授权了什么，当前调用能否用已观测事实证明仍属于该授权。**

## 2. 三阶段方法

```text
可信用户请求 + 工具／效果契约
              │
              ▼
① 授权编译
   自然语言 → 授权 DAG
   效果、参数槽、来源、条件、委托和预算
              │
              ▼
② 程序化运行时证明
   工具调用 + 参数 + 返回 + 来源 + 状态版本
              │
        ┌─────┼─────┐
      ALLOW  REVIEW  ALERT
              │
              ▼
③ 证明义务驱动的局部语义审计
   失败原因 → 原子谓词 → 图上证据切片
   SUPPORTED / CONTRADICTED / NEED_EVIDENCE
```

### 阶段一：授权编译

编译器只读取可信用户消息、Agent 能力和工具 schema，生成有限授权 DAG。它表达用户允许的终端效果、固定参数、可由运行时来源补全的动态参数、约束、委托和预算，不把某一条预生成工具序列当成唯一正常计划。

### 阶段二：程序化运行时证明

宿主侧在工具网关记录调用、参数、返回字段、来源和状态版本，用有限算子证明投影、筛选、范围传播、能力派生和预算消费。证明完整则放行；存在明确效果、范围或参数冲突则告警；缺少关系证据则进入复核。该阶段不调用额外 LLM。

### 阶段三：证明义务与局部语义审计

程序不把整个 REVIEW 轨迹交给 LLM，而是先把失败原因转成一个有限的证明义务，例如“这个收件人是否来自用户允许的文件字段”“这个网页读取是否仍在授权来源范围”“这个中间操作是否服务于授权终端效果”。随后从执行图切出可信请求、候选调用和相关来源节点组成证明包。

LLM 只能输出：

- `SUPPORTED`：证据证明当前具体调用；
- `CONTRADICTED`：存在有限冲突，并提交可程序校验的冲突证书；
- `NEED_EVIDENCE`：指出缺失事实和建议查询，不强制猜测。

首次证据不足时最多扩展一次已有执行证据。仍无法证明的调用保持不可判定；安全替代只是部署时控制高影响未知操作的可选网关，不计作原任务完成，也不是当前方法的主要实验贡献。

## 3. 当前全量结果

下表合并了授权 DAG、程序证明和证明义务审计。攻击统计只包含实际存在攻击目标调用的组合。

| Benchmark | 数据 | ALLOW | REVIEW | ALERT |
|---|---|---:|---:|---:|
| AgentDojo | 正常任务（97） | 86（88.7%） | 9（9.3%） | 2（2.1%） |
| AgentDojo | 有效攻击（609） | 0 | 101（16.6%） | 508（83.4%） |
| AgentDyn | 正常任务（60） | 33（55.0%） | 25（41.7%） | 2（3.3%） |
| AgentDyn | 攻击（560） | 0 | 193（34.5%） | 367（65.5%） |
| **合计** | **正常任务（157）** | **119（75.8%）** | **34（21.7%）** | **4（2.5%）** |
| **合计** | **有效攻击（1,169）** | **0** | **294（25.1%）** | **875（74.9%）** |

阶段三 v2 只能自动放行 101/157 个正常任务；证明义务审计将其提高到 119/157，同时没有放行任何有效攻击。高置信攻击告警从 682/1,169 提高到 875/1,169。

原始 benchmark 标签下有 4 个正常任务被告警。证据审查显示四条轨迹分别存在错误日期、未授权网站访问、错误账户和错误效果实现，均具有可复核冲突。报告不删除这些样本，但将“benchmark 标为正常”与“调用事实上符合请求”分开呈现。

上述数字来自冻结轨迹上的授权回放，只说明候选调用能否得到授权证明；不能直接等同于重新执行 Agent 后的任务完成率或攻击成功率。

## 4. 当前结论和下一步

目前已固定的方法主线是：**授权 DAG 定义允许范围，程序证明覆盖明确关系，证明义务审计解释剩余局部语义。** 它比“完整轨迹二分类”多了一层可验证接口：LLM 不决定整项任务是否安全，而只回答一个由程序产生、带证据引用的有限问题。

当前瓶颈不是攻击直接漏放，而是 34 个正常任务仍缺少足够证据。下一步只做一个推进：把审计器返回的 `missing_fact + suggested_query` 接入真实只读补证或局部重放，检验能否进一步证明正常动态扩展，同时保持攻击 `SUPPORTED=0`。不再通过已知 case 专用规则提高表面数字。
