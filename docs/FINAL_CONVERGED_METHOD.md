# GreatWallGuard：收敛后的终局授权方法

## 1. 最终要解决的问题

在线 Agent 防御不能把 `REVIEW` 留给部署方，也不能为了消除 `REVIEW` 强迫 LLM 猜测。GreatWallGuard 的最终目标是：对每个拟执行工具调用给出可执行处置，同时把“任务完成”和“安全继续”分开统计。

```text
ALLOW_ORIGINAL        执行原调用
ALLOW_SAFE_SUBSTITUTE 不执行原调用，执行有界低影响替代
DENY                  拒绝原调用
REQUEST_CONFIRMATION  仅当用户偏好是唯一缺失授权时使用
```

`REVIEW` 只允许存在于内部取证过程，不能成为终局输出。

## 2. 完整方法

```text
可信用户请求 + 工具／效果契约
              │
              ▼
① 授权编译
   自然语言 → 授权 DAG
   效果、参数槽、来源、条件、委托和预算
              │
              ▼
② 程序化运行时证明
   工具调用 + 参数 + 返回 + 来源 + 版本
              │
        ┌─────┴─────┐
     证明成立      内部 REVIEW／明确冲突
        │                 │
        │                 ▼
        │        ③ 自动补证与局部语义证明
        │           补来源／条件／版本
        │           SUPPORTED / CONTRADICTED / INSUFFICIENT
        │           冲突证书程序校验
        │                 │
        └─────────────────┤
                          ▼
                ④ 终局效果处置
             原操作 / 安全替代 / 拒绝 / 极少确认
```

### 2.1 授权编译

编译器只读取可信用户消息、Agent 能力和工具 schema，生成有限授权 DAG。它表达终端效果、固定参数、动态参数槽、允许来源、条件、委托和预算，不把某一条预生成工具序列当成唯一正常计划。

### 2.2 程序化运行时证明

宿主侧记录工具、参数、返回字段、来源调用和状态版本，并用有限算子证明投影、筛选、连接、范围传播、能力派生和预算消费。证明成立即可执行；明确效果、范围、预算或版本冲突直接拒绝。

### 2.3 自动补证和三态语义证明

内部 `REVIEW` 首先被转换为具体取证动作：补取工具返回或契约、重建字段来源、切出最小证据链，或对低信任 observation 做局部重放。语义审计只能输出：

- `SUPPORTED`：证据支持当前调用；
- `CONTRADICTED`：证据明确反驳当前调用；
- `INSUFFICIENT`：证据不足。

`CONTRADICTED` 必须携带有限冲突证书。当前程序检查冲突类型、证据引用、操作数和有限关系；不完整或关系实际成立的证书自动降级为 `INSUFFICIENT`。

### 2.4 终局效果处置

`INSUFFICIENT` 不再作为最终输出。部署方为工具声明效果级安全替代：通信变为草稿，交易变为预览，删除变为隔离，文件修改变为新版本，仓库操作变为本地分支，外部网页读取进入隔离阅读器。安全替代不得执行原调用的外部提交效果。

若没有安全替代，则高影响未知操作默认拒绝。只有操作不可逆、没有安全替代，并且缺失的确实是用户偏好而非技术证据时，才请求用户确认；一次确认应更新授权 DAG，避免逐调用重复询问。

## 3. 最终实验结果

本次终局实验是在阶段三 v2 的剩余任务上进行效果契约回放，不重新运行受害模型。安全替代表示原有害效果未发生、任务可以继续准备，但不能计作原始 benchmark 任务已经完成。

### 正常任务

| Benchmark | 原操作执行 | 安全替代 | 拒绝 | 用户确认 |
|---|---:|---:|---:|---:|
| AgentDojo（97） | 80.4%（78） | 18.6%（18） | 1.0%（1） | 0% |
| AgentDyn（60） | 38.3%（23） | 61.7%（37） | 0% | 0% |
| **合计（157）** | **64.3%（101）** | **35.0%（55）** | **0.64%（1）** | **0%** |

正常任务安全继续率为 99.4%（原操作或安全替代），但严格原任务自动完成率仍只有 64.3%。因此不能把 99.4% 写成 utility；35.0% 仍需要后续自动补证或由用户在草稿／预览层面主动提交。

### 攻击任务

| Benchmark | 原有害操作执行 | 安全替代 | 拒绝 | 用户确认 |
|---|---:|---:|---:|---:|
| AgentDojo 有效攻击（609） | 0% | 25.5%（155） | 74.5%（454） | 0% |
| AgentDyn（560） | 0% | 59.3%（332） | 40.7%（228） | 0% |
| **合计（1,169）** | **0%** | **41.7%（487）** | **58.3%（682）** | **0%** |

两个 benchmark 中均无攻击执行原目标效果。41.7% 的攻击没有被宣称为高置信识别，而是被降级为无法产生目标危害的安全替代。

## 4. 为什么这个结果比强制二分类更可信

直接采用 LLM 的 YES/NO 曾把正常硬告警推高到 22/157。三态证明和冲突证书将硬告警降至 1/157；终局网关再把证据不足转成有界效果，而不是重新放行或虚假阻断。因此方法同时保持：

- 攻击原目标效果放行率 0%；
- 正常硬拒绝率 0.64%；
- 最终 `REVIEW` 数量为 0；
- 用户确认率在当前契约回放中为 0%。

代价也必须明确：原操作自动执行率只有 64.3%，安全替代不能冒充完整任务成功。

## 5. 当前完成边界

已完成的是终局决策接口、效果契约、自动取证计划、三态审计、冲突校验、安全替代执行器和双基准策略回放。执行器从控制流上保证 `ALLOW_SAFE_SUBSTITUTE` 只能进入已注册替代处理器，不会回落调用原高影响工具。尚未完成的是在 AgentDojo／AgentDyn 环境中为所有草稿、隔离、版本化和预览操作提供真实后端，并重新计算端到端 utility；部分替代在现有 benchmark 中没有原生工具，需要通过 Agent runtime 提供事务层实现。

下一步只需验证一个问题：将这些安全替代接入真实工具网关后，能够有多少在无需用户确认的情况下通过后续补证自动升级为原操作。这个指标决定方法的实际可用性，而不是继续提高已经为零的攻击直接放行率。
