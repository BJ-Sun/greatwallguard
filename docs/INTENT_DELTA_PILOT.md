# 用户意图提取：授权增量的首轮离线试验

## 问题与最小表示

当前图记录 Agent 做了什么；检测还需要一个**只能由用户侧更新**的 TaskScope，说明哪些可产生持久副作用的动作被要求或允许。长程任务里，这不是一次性工具白名单：用户可以先要求准备资料、下一轮才授权发送；收件人或正文也可能需要从任务资料中确定。

本试验把每轮用户消息解析为三种“增量”，而不从 Agent 行为或工具返回反推授权：

| 增量 | 意义 | 例子 |
| --- | --- | --- |
| `grant` | 授权一个效果及其参数约束 | 发送给明确地址；或发送给项目记录中**经验证**的负责人 |
| `constraint` | 限制授权及其有效期 | “这一步不要发送邮件”，仅在该轮有效 |
| `unresolved` | 可能涉及效果但不足以扩权 | “继续剩余的沟通工作”不等于授权第二封邮件 |

每个 `grant` 的关键参数不是简单的“已知/未知”二分，而是 `literal`（用户明确给出）、`reference`（指代先前用户信息）、`task_data`（用户指定从任务资料中求值，须验证来源和选择条件）。例如“给项目负责人发状态邮件”的收件人不是任意工具返回中的地址，而是一个尚未实例化的条件参数。参数值由执行环境提供，不会因此获得修改授权规则的能力。

运行时先用这些增量产生版本化 TaskScope，再拿图中的实际 Effect 与授权模板比较。对于 `task_data`，若当前图无法证明参数如何从指定资料得到，结论应是**待核实**，既不能默认为授权，也不应直接判攻击。这是表示层定义，不是已验证的完整检测器。

## 已做的试验

冻结的 53 条 `request_only` 用户消息中选了 5 组，再加入 3 组近期真实 OpenClaw 正常邮件任务的**用户消息投影**，共 8 组。选择覆盖双文件分享、同轮双邮件、跨轮“先不发后发送”、日程从邮件确定时间、含糊的续办，以及真实运行暴露出的跨句发送授权和资料决定收件人。8 组参考事件共含 10 个授权、4 个本轮约束、3 个待澄清表达。

本地验证程序先检查每个参考事件的证据片段确实存在于对应用户轮次，再将旧的平面规则提取器与这些参考事件比较。它**不读取攻击标签、执行轨迹或成功 oracle 来生成提取结果**。两者的比较仅用于定位表示缺口：

| 检查点 | 观察 |
| --- | --- |
| 动作种类 + 轮次 | 旧规则找到 8/10 个参考授权；漏掉的两个都是真实正常任务中的邮件发送表达 |
| 参数 | 在已匹配授权中仍有 7 处参数表示缺口：邮件正文、日程事件/时间以及从资料确定的正文 |
| 时效与不确定性 | 旧平面规则没有 4 个本轮约束的状态，也不把 3 个含糊续办表达为“不扩权”的待澄清状态 |

这**不是提取准确率、误报率或检测收益**：8 组是有目的选取的困难样本，参考事件由助手编写、并非独立人工真值；旧规则也曾在部分相似样本上开发。`7` 是已匹配动作上的参数缺口次数，不包含两个完全漏提的授权。三组真实正常任务中，只有一组发生了发送，且其固定正文 oracle 不适合评价动态生成正文；这里不声称任务成功率。

## 最重要的设计判断

TaskScope 不宜表示为“允许调用 `send_email`”或“当前看到过的参数集合”。它应是**用户证据支持的、随轮次增量更新的效果约束**。比较图中的 Effect 时，先问“该效果属于哪个用户授权模板”，再问“关键参数是用户字面值、用户指代，还是用户指定资料的受约束求值”。这样能把两类容易混淆的情况分开：正常任务中尚未求值的参数，与攻击步骤从外部内容引入的新目的地。

目前的 reducer 只演示一种必要的时序语义：“此步不发送”不自动否定下一轮明确的发送授权；含糊续办也不会产生新的授权。还没有实现撤销、修订、冲突优先级和跨任务隔离，不能把这一数据结构直接作为线上阻断依据。

## 下一轮验证门槛

1. 冻结一份独立于规则开发者的用户消息标注规范与测试集；由至少两位标注者分别标注 `grant / constraint / unresolved`、关键参数来源和有效期，并记录分歧。
2. 先检验**只看用户消息**能否稳定提取授权增量；特别加入正常任务的多种表达、取消/修改任务、资料决定参数和恶意输入伪装授权。不要通过观察完整 trace 来倒填 TaskScope。
3. 在真实 Agent 执行时逐轮冻结 TaskScope 版本；针对需要资料求值的参数，只将图作为证据核实工具。比较“规则直接放行/阻断/待核实”三种决策在正常与攻击执行上的误报、漏检及待核实比例。

复跑：`python3 experiments/intent_delta_pilot/evaluate.py`；测试：`python3 -m unittest discover -s experiments/intent_delta_pilot -p 'test_*.py'`。参考草稿和程序分别位于 `experiments/intent_delta_pilot/reference_draft.json` 与 `experiments/intent_delta_pilot/evaluate.py`。本试验只在本地仓库开展，不向外部模型发送这些用户消息。
