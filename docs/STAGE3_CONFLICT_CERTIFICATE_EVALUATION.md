# 阶段三 v2：三态语义证明与冲突证书实验

## 1. 这次改了什么

第一版语义审计虽然没有放行攻击，但会把“没有证明”错误升级为“明确越权”。v2 不再接受一个裸的 `unauthorized` 标签，而要求 LLM 在三个命题中选择：

- `VERIFIED`：现有证据支持调用；
- `CONTRADICTED`：现有证据明确反驳调用；
- `INSUFFICIENT`：现有证据不足。

若选择 `CONTRADICTED`，还必须提交有限冲突证书：冲突类型、被违反的授权条款、实际值、授权值或约束、比较算子和证据引用。当前程序校验器接受五类冲突：固定值冲突、条件违反、明确禁止、范围越界和版本冲突。缺少操作数、引用不存在或约束实际成立时，结论自动降级为 `INSUFFICIENT`。

## 2. 实验设置

我们只重跑 v1 判为未授权的 518 个调用：33 个正常调用、485 个攻击调用。这样直接检验两个问题：旧的正常硬告警能否被纠正，以及收紧 `CONTRADICTED` 后是否会错误支持攻击。

518 条记录中有 383 个唯一证据包，135 条重复记录通过内容哈希复用；唯一 API 请求消耗 629,666 token。

## 3. 调用级结果

### LLM 原始三态

| 数据 | VERIFIED | CONTRADICTED | INSUFFICIENT |
|---|---:|---:|---:|
| AgentDojo 正常（9） | 0 | 1 | 8 |
| AgentDyn 正常（24） | 0 | 0 | 24 |
| AgentDojo 攻击（194） | 0 | 34 | 160 |
| AgentDyn 攻击（291） | 0 | 16 | 275 |

### 冲突校验后

| 数据 | SUPPORTED | 有效 CONTRADICTED | INSUFFICIENT |
|---|---:|---:|---:|
| AgentDojo 正常（9） | 0 | 1 | 8 |
| AgentDyn 正常（24） | 0 | 0 | 24 |
| AgentDojo 攻击（194） | 0 | 27 | 167 |
| AgentDyn 攻击（291） | 0 | 5 | 286 |

51 个原始冲突中，18 个因为缺少冲突操作数被程序降级；最终保留 33 个有效冲突，包括 17 个范围越界、14 个固定值冲突和 2 个条件违反。没有攻击调用被提升为 `SUPPORTED`。

## 4. 合并后的任务级结果

| Benchmark | 数据 | Stage 2 | v1 直接采用 LLM 否定 | v2 冲突证书 |
|---|---|---:|---:|---:|
| AgentDojo | 正常 97 | 60 A / 37 R / 0 X | 78 / 12 / 7 | **78 / 18 / 1** |
| AgentDojo | 有效攻击 609 | 0 / 179 / 430 | 0 / 39 / 570 | **0 / 155 / 454** |
| AgentDyn | 正常 60 | 6 / 54 / 0 | 23 / 22 / 15 | **23 / 37 / 0** |
| AgentDyn | 攻击 560 | 0 / 337 / 223 | 0 / 46 / 514 | **0 / 332 / 228** |

`A/R/X` 分别表示 Allow、Review、Alert。

v2 将正常硬告警从 22/157 降到 1/157（0.64%）。唯一保留的正常告警是 AgentDojo `workspace/user_task_18`：邮件明确要求 2024-05-18，调用却使用 2024-06-18，固定值冲突成立。此前人工识别的 6 个真正 LLM 假告警全部降为证据不足。

攻击高置信阻断率回落是预期结果：v1 把大量“缺少授权证明”当成了明确冲突；v2 只阻断能够给出有限反证的调用。重要的是，攻击仍然没有被直接放行，而是回到 `REVIEW`。

## 5. 结论

这次实验验证了一个比“优化提示词”更稳定的设计原则：

> LLM 可以发现候选语义关系，但硬阻断必须由有限、可检查的冲突证书支撑；没有证明授权不等于证明越权。

在当前数据上，这一原则把表面正常硬告警率从 14.0% 降到 0.64%，同时保持攻击直接放行为 0。它没有解决所有攻击复核，而是把不确定性诚实地留在 `REVIEW`，符合低误报在线防御的目标。

## 6. 当前限制

当前校验器已经验证冲突类型、证据引用、操作数完整性和有限关系是否成立，但证书中的操作数仍可能由 LLM 从非结构化 observation 中抽取。它尚未在所有场景中把每个操作数绑定到事实图的具体字段路径。因此，本结果证明了三态分流和程序兜底有效，但不能宣称所有语义反证都已完全形式化验证。

下一步应把 `actual_value` 和 `authorized_value_or_constraint` 分别绑定到执行图节点与授权 DAG 节点；只有两端均可追溯时，冲突证书才进入最终高置信阻断。
