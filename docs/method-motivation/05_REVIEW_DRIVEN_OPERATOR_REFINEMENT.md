# 第五步：由复核归因驱动通用算子完善

## 为什么不能继续盲目增加规则

类型化来源绑定后，97个 AgentDojo 正常任务中仍有45个进入复核。逐条检查表明，它们并非同一种失败：有些只缺少聚合或算术关系，有些需要理解摘要和角色，有些是用户把操作权开放交给外部内容，还有少量官方轨迹与用户条件并不一致。

如果把所有复核都当成“规则覆盖不足”，会产生两类错误：为语义任务添加 benchmark 补丁，或者把含糊外部委托错误扩张成权限。因此，本轮采用一条固定原则：**只有能够由结构化事实唯一重放、且可跨任务复用的关系，才进入正向算子集合。**

## 从失败类型到方法改动

### 重复实体去重

同一文件可能同时出现在 `list_files` 和另一条文件查询结果中。旧实现把它们当成两个候选，导致唯一最大值证明失败。新实现根据稳定对象 ID 去重，再执行 `argmax/argmin`。这解决了复杂前置查询之后的“删除最大文件”。

### 跨调用分组聚合

部分任务需要多次读取后再比较：逐频道查询成员数，或汇总所有频道消息并统计发送者。新算子按照调用参数形成分组，计算 cardinality/frequency，再证明唯一最大值。工具调用的先后顺序不参与判定。

### 排名与有限模板实例化

对于“按活跃度排序，并向第 k 名发送对应消息”，系统先按消息数排序、按用户名处理并列，再核对消息中的名次。模板只允许替换用户明确声明的有限占位符；任意自由生成正文仍不能由此放行。

### 结构化记录投影与确定算术

交易任务被表示为：按用户给定账户或服务筛选记录，投影金额，再执行用户明确给出的算式，例如：

```text
refund_amount = received - total / 2
price_difference = previous_payment × 10%
vat_difference = previous_payment × 19.5% + fee
```

每份证明保存来源调用和算术输入。候选记录不唯一、方向不符或计算结果不一致时保持复核。

### 安全关键字段契约

工具的所有参数不应默认具有相同安全意义。即时转账的授权核心是收款方和金额；备注和主机记账日期保留为证据，但不应因为用户未逐字指定而阻断。定时交易的执行日期和周期仍属于关键字段。部分更新工具也只检查本次调用实际修改的字段，不能要求不存在的可选字段。

### 可重放的条件守卫

参数正确不代表条件分支已经获准。例如“评分高于4才预订”还要求证明评分谓词成立。系统把这类条件编译为可由先前 observation 重放的类型化谓词；证据缺失或条件不成立时保留复核。守卫不能退化为 `if` 关键词规则，否则会误伤具有不同条件语义的日历任务。

## 全量实验结果

| 阶段 | 正常自动放行 | 正常复核 | 新增合法证明的攻击调用 |
|---|---:|---:|---:|
| 仅效果授权 | 38/97 | 59/97 | — |
| 初步正向证明 | 50/97 | 47/97 | 0 |
| 类型化来源绑定 | 52/97 | 45/97 | 0 |
| 复核驱动算子完善 | **60/97** | **37/97** | **0** |
| 类型化条件守卫 | **61/97** | **36/97** | **0** |

相对类型化来源阶段，关系算子新增放行8个正常任务，条件守卫再新增1个。629个攻击组合仍为413个告警、175个复核和41个放行；其中20个没有目标调用，21个是只读网页目标。所有新增算子的 `proved_attack_calls` 均为0。

## 这一步形成的方法原则

正向算子不是越多越好，而应满足四项准入条件：

1. 输入来自执行前已观察、带调用 ID 的结构化事实；
2. 关系具有任务无关的确定语义，可以重放；
3. 结果唯一，冲突或缺失证据返回 `REVIEW`；
4. 同一改动同时在正常任务和攻击对照上验证。

因此，程序化能力的推进单位不再是“新增一个句式”，而是“新增一个可证明关系类别”。

## 剩余边界

最新仍有36个任务复核：7个尚可通过可重放关系处理，20个需要内容或角色语义，5个属于开放式外部委托，4个是 benchmark/工具契约问题。详细分类见[最新复核归因](../AGENTDOJO_NORMAL_REVIEW_TAXONOMY_V27.md)。下一步只继续验证类型化模板与实体依赖；程序关系无法唯一证明的字段进入局部语义审计，而不是继续增加句式规则。
