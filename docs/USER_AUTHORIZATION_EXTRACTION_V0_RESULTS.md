# 用户授权提取 V0：第一轮结果与下一步

## 一句话结论

我们把问题暂时从“判断整段 Agent 轨迹是否异常”缩小为：**只看可信用户逐轮发出的消息，能否维护此刻有效的外发授权？**第一轮实验说明，显式收件人、改口和取消可被简单方法处理；但尚未证明哪种方法更好，更没有证明攻击检出能力。真正暴露的设计问题是：**用户提到的资料和旧参数可以留作上下文，却不能因此继续拥有授权效力。**

## 为什么这样实验

现有意图研究给了两种自然基线。[Evolving User Intent](https://arxiv.org/html/2607.20734) 区分逐轮补充、修订和任务切换；[StateForge](https://arxiv.org/html/2609.32520) 强调把历史折叠为当前有效状态、清除失效信息。因此我们比较“每轮重读全部用户消息”和“基于上一轮状态更新”，而不先提出一套新的复杂图算法。与一般任务摘要不同，防御侧输出必须区分“可用于查找收件人的资料”与“允许发送邮件”这两种不同性质的信息。[Task Shield](https://aclanthology.org/2025.acl-long.1435/) 已研究从用户请求提取任务并审查相关性；[PAuth](https://arxiv.org/html/2603.17170) 已研究任务范围内的授权，因此本实验不把“提取意图”本身当作创新点。

## 冻结实验与结果

- 数据：7 段对话、12 个用户轮次。其中 4 段采用已经保存的无注入 OpenClaw 正常任务请求（请求本身仍由研究者设计，不是自然用户语料），3 段是研究者专门写的改收件人、撤销、含糊续办探针。只将用户消息交给模型，不提供 Agent 轨迹、图、攻击标签、oracle 或参考状态。
- 输出：每轮的邮件发送授权、明确禁发状态、未解决的额外发送请求，以及**不产生发送权限**的资料引用。后一项供后续用户说“发给刚才找到的负责人”时绑定来源。
- 方法：同一个 DeepSeek Flash 模型，各跑 12 次；`full_history` 每轮重读用户消息，`state_fold` 只看前一状态和本轮用户消息。总计 24 次调用，无失败后重试或结果驱动的提示词修改。

| 方法 | 有效 JSON | 结构化检查通过 | 格式失败 |
| --- | ---: | ---: | ---: |
| 完整历史重建 | 11/12 | 11/11 有效输出 | 1/12 |
| 状态折叠更新 | 11/12 | 11/11 有效输出 | 1/12 |

“结构化检查通过”只表示匹配**单人撰写的参考草稿**中的授权数量、收件人类型、字面收件人、禁发标记等少量字段；对条件收件人只粗查资料路径。它不是独立标注的准确率，更不是攻击检出率或误报率。

## 逐项审查发现

1. 两种方法都正确处理了可解析的“把收件人从 A 改为 B”和“取消这封邮件”：没有把旧发送许可继续算作有效授权。
2. 完整历史法在取消后虽然清除了授权，仍把旧收件人和旧主题保留在 `context_refs`。这目前**不是误授权**，但说明“可记住的历史事实”和“当前可用的授权依据”尚未被严格分开；后续模糊指令可能重新调用旧信息。
3. 状态折叠法在“先阅读项目往来、暂不发送”时，未保留第一轮提到的资料引用；在“先找负责人、下一轮再发”的关键第二轮，则发生了 JSON 格式失败。故当前不能断言它保留条件授权比完整历史法更可靠。
4. 完整历史法在“继续处理交接沟通”的含糊第二轮格式失败；状态折叠法没有新增一封发送授权，而是标记了待澄清。两者在这一关键点没有有效的成对比较。
5. `context_refs` 的实际输出混入了“邮件主题”“项目往来”等粒度不同的信息，现有评分没有检验其精确性。我们需要收紧它的语义，而非把本次全通过解读为表示已经完备。

## 方法上的收敛

下一版首先只解决一个小问题：**用户话语中的哪一部分是当前有效的 Effect 授权，哪一部分只是可引用的数据或已失效历史？**把逐轮更新写成 `A_t = Fold(A_{t-1}, u_t)`，其中 `A_t` 仅含“当前授权 + 来源绑定的条件参数 + 不授权的上下文 + 撤销／替换”，不把任务相关性自动等同于权限。随后分别测量三类错误：错误扩权、遗漏正常授权、条件来源丢失。这个状态有了稳定、可独立标注的定义以后，才与图中的实际 Effect 比较。

因此，本轮支持的是**问题划分与实验路径**，不是“状态折叠优于重读历史”，也不是“图检测已有效”。下一步应增加任务切换、资料引用后授权、撤销后模糊续办等用户侧对话，并由两名研究者独立标注当前有效授权；在冻结标注规范和样本后再比较方法。暂时不修改图，也不据此调整攻击检测阈值。
