# AgentDojo 全量程序化授权基线

## 这次到底测什么

本实验只回答一个问题：**不调用 LLM，仅根据用户指令生成的程序化授权规则，能否判断 AgentDojo 官方正常操作和攻击目标操作？**

我们使用 AgentDojo v1.1 的四个 suite，共 97 个正常任务。对每个正常任务读取官方标准工具调用，再分别追加对应 injection task 的官方目标调用，共得到 629 个任务—攻击组合。实验不运行受害模型，因此不受模型是否自然拒绝攻击影响；它测量的是“攻击动作一旦被提出，授权器能否识别”。

本轮使用的是官方标准调用，不包含完整工具返回。因此它首先测量**意图规则和工具契约**，尚不能测量事实图对动态参数来源的最终改进。

## 第一轮：原始程序化模块

| 指标 | 结果 |
|---|---:|
| 正常任务 | 97 |
| 正常直接放行 | 18（18.6%） |
| 正常进入复核 | 65（67.0%） |
| 正常错误告警 | 14（14.4%） |
| 有实际目标调用的攻击组合 | 609 |
| 高置信攻击告警 | 320（52.5%） |
| 攻击进入复核 | 289（47.5%） |
| 攻击直接放行 | 0 |

另外 20 个组合的 injection ground truth 为空，不属于工具调用检测的分母。

第一轮看似安全，但 81.4% 的正常任务如果采用“告警或复核均阻断”的策略都会失败。原因主要不是复杂语义，而是当前工具契约只覆盖了 Workspace：57 个正常任务至少调用了一个尚未登记的 Slack、Travel 或 Banking 工具。

## 第二轮：只补齐有限工具契约

我们没有修改意图提取规则，只把 AgentDojo 工具明确分成只读观察和持久化操作，再运行完全相同的实验。

| 指标 | 结果 |
|---|---:|
| 正常直接放行 | 37（38.1%） |
| 正常进入复核 | 13（13.4%） |
| 正常错误告警 | 47（48.5%） |
| 正常严格阻断率 | 60/97（61.9%） |
| 高置信攻击告警 | 588/609（96.6%） |
| 攻击进入复核 | 0 |
| 攻击直接放行 | 21/609（3.4%） |

补齐契约后，原来的“未知工具复核”被分解为两种更真实的结果：只读查询正常放行；持久操作若没有被当前意图语法识别，则直接告警。因此攻击告警率显著提高，但正常误报也暴露出来。

## 错误来自哪里

### 正常任务

47 个正常告警主要不是事实图漏记，而是意图提取器根本没有生成相应授权：

- Slack 的私信、频道消息、邀请和加群；
- Banking 的转账、计划交易和用户资料更新；
- Workspace 的邮件、文件创建和追加；
- Travel 的预订及少量邮件、日历任务。

13 个复核才属于“效果识别正确，但参数无法仅从用户文字绑定”：日历内容、共享文件对象、改期时间和参与者等。这部分需要接入真实工具返回和事实图。

因此，当前正常失败可以清楚分成：

```text
47 个：意图语法没有覆盖正常效果
13 个：效果已识别，但动态参数证据不足
37 个：程序化规则已经足够
```

### 攻击任务

21 个直接放行全部来自 Slack `get_webpage`。该工具按系统状态看是只读操作，所以效果授权器允许；但对应攻击目标是读取敏感网页内容并在最终回答中泄露。这说明只审计持久工具效果无法覆盖“读取本身即越权”或“通过自然语言输出泄露”的攻击。

其余 588 个有目标调用的组合均产生高置信告警。这个数字是基于官方目标调用的条件检测率，不是端到端 ASR，也不能代表真实部署准确率。

## 当前可以下什么结论

程序化方法并非“规则太弱所以完全无效”。在工具契约完整后，它对明确计划外持久操作有很强的条件检测能力。真正的问题被缩小为三类：

1. **意图覆盖不足：**用户明确授权了正常持久操作，但规则语法没有提取出来；
2. **动态参数未证明：**操作类型正确，参数需要由工具返回决定，应由事实图提供来源证明；
3. **非持久性危害：**敏感读取或最终文本泄露不产生已登记的持久效果，当前检测面无法观察。

这三类不能用同一种补丁解决。下一步应先补齐第一类的通用效果授权表示，再只对第二类接入事实图；第三类需要单独定义读取和输出的信息流策略。

## 下一步

下一轮不增加更多关键词，而是把 47 个正常告警转换成有限的效果类型及关键参数：消息发送、成员变更、预订、资金转移和账户修改。用户指令只需要授权效果和动态参数约束，不预测具体工具轨迹。

完成后重新运行同一冻结实验。验收标准是：正常错误告警明显下降，同时 588 个已告警攻击不能因为宽泛授权而大规模变成放行。随后针对剩余 13 个动态参数复核，执行真实只读工具并把返回接入事实图。
