# 图表征规范：过程关系与内容命题

目标：把 Agent 长程活动压缩成可回查的结构，使后续监控能够判断任务、行为和累积影响的关系。图构建阶段不判断攻击。

## 一个统一定义

```text
表征 = 过程图 G + 内容索引 C + 原始证据 R

输入被看到 → 动作被发起 → 影响被报告 → 状态版本被记录
    O             A            E              S
    │             │                           │
    └── 内容引用 ─┴─────────────── 有快照时引用 ─┘
                  ↓
        C：带原文位置、来源和顺序的关键片段
                  ↓
        R：网页、消息、参数或文件快照
```

G 表达事件与对象之间的关系；C 表达内容中的事实、要求和约束；R 支持核查与重新抽取。三者分别记录大小，不能把原文外置的成本算作消失。

“内容 / 过程”是两种表征职责，不是两套竞争的节点分类。Observation 是一次看到内容的事件；State 是一个对象的版本，两者都不等于完整文本。Action 参数也有复杂内容，因此内容索引是共享机制，而不是仅给 Observation 加字段。

## 节点和边的稳定含义

| 节点 | 表达的问题 | 产生依据 |
|---|---|---|
| Observation | 哪次输入或返回进入了观测边界？ | 用户/上下文加载/工具返回/可见模型输入输出 hook |
| Action | 哪次操作被发起？ | 调用及后台操作 hook |
| Effect | 此操作预期或报告了什么影响？ | 工具契约、适配器或推断规则 |
| State | 某对象记录到了哪个版本？ | 成功回执或状态快照，必须标明依据 |

| 边 | 关系 | 当前采集器的证据强度 |
|---|---|---|
| derived_from | 候选来源关联 | 接入模型边界时记录调用上下文与输出的关联；其余仍近似最近 Observation；均不证明因果使用 |
| causes | 动作对应的影响描述 | 工具名规则推断；后台适配器声明 |
| updates | 影响对应的版本记录 | 有前后快照时仅在指纹变化后产生；其他适配器仍依据回执报告 |
| reads | 观测关联历史对象版本 | 有指纹时同时核对对象和内容；不一致则标记不匹配，不连到旧版本；其余仍按对象 ID 推断 |
| next | 同一步内节点的记录顺序 | 本地插入顺序；不解释为控制依赖 |

每条边使用同一个证据结构：`basis + method`。basis 取 observed（直接观测）、reported（回执报告）、declared（契约声明）、inferred（推断）、unspecified（未声明）。它们不是准确率分数。后续工具契约或版本校验只改善证据，不新增一套图结构。

当前单步一个 Effect 是采集器的简化，而非理论限制。真实文件适配器已记录可见模型输入输出（含工具 schema）并核验文件内容版本。复杂 Bash 内部影响、真实因果依赖、并发和通用外部状态验证仍未完成；黑盒内部推理不在可观测范围。文件内容指纹不涵盖权限、时间戳等元数据。

## 内容的初步可用设计

先实现抽取式压缩：确定性地按段落分块，短内容完整保留；超过单份预算时，LLM 只选择关键段落 ID。代码从原文复制相应片段，保留来源、字符位置和原始顺序，报告未选中或超预算的片段。相同内容只选择一次，来源事件仍分别保留。

```text
原文分块 → 选择块 ID → 按原文顺序取回片段 → 附上来源/会话/位置

保留：“旧的 Bob 方案已撤回。现在的接收人是 Carol，审批尚未通过。”
字段：source_ref、start、end、原文 text；事件层保存 source、session、order。
```

这样不需要模型重新表述主体、否定或条件。第一轮的命题式提取接口仍保留为实验基线，但已有实验发现主体歧义、否定类型错误和撤回关系丢失，暂不作为监控依据。

段落只是初步单元，不保证语义闭合：跨段指代、跨文档修订以及单个超长段落仍可能失真。预算不足时整段省略并标记，不能无损压缩的内容需要回查原文。模型可能选错段落，因此所有结果标为 partial；片段原样复制也不证明内容本身真实或已获授权。

内容选择发生在采集之后。评估时不给选择器看测试问题或答案，比较原文、相同单份预算下的前缀截断和抽取式视图，检查对事实、禁止、条件和修订问题的回答是否正确。

## 有界的究竟是什么

完整过程图和原始证据随执行增长。运行时视图受状态数和动作数预算限制；单份内容摘要受字节预算限制。它们都不等价于“长程信息已无损保留”。

相同内容用全文 SHA-256 去重，事件仍各自保留。内容索引是显式启用的实验功能：默认不存原文，启用时原文与图分开导出。现在内容索引供离线评估使用，尚未接入 compact_view 的全局检索预算。文件 State 已可附内容指纹，但仍不直接存完整文件正文；可见模型输入的完整快照会增加证据存储成本，不能称为总存储有界。

## 用问题定义保真度

先固定四类可回答的问题：

1. 用户要求什么，禁止什么，有哪些前置条件和后续修订？
2. 某内容来自谁、在哪一轮出现，外部建议是否仍保持原来源？
3. 操作针对哪个对象、报告何种结果，哪些影响尚未核验？
4. 哪个历史对象在后续被读取，版本关联基于什么证据？

过程侧用独立调用记录和状态快照验证关联的精确率与召回率；内容侧以预先标注的事实/限制检查保留和误表述。分别报告图大小、内容摘要大小、原文存储、抽取耗时与回查次数。摘要越短却回答错误越多，就不能称为更好的压缩。

当前落地：统一证据属性、模型边界采集、文件内容快照核验、独立过程对照、可选内容索引和关键片段压缩。实际结果和观测范围见 [双维度真实执行验证](../experiments/TWO_AXIS_VALIDATION.md)。后续按上述问题暴露的信息损失推进，不为攻击子类逐个追加规则。
