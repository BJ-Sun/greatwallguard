# 阶段同步：低成本程序化授权检查

## 1. 目标与方法

我们先验证一种低成本、可在线运行的程序化方法能做到什么：从可信用户消息中提取允许的操作、对象和参数，并在每次工具调用前逐字段检查。该过程不调用额外 LLM。

```text
用户消息 → 授权规则 → 检查工具调用
                       ├─ 明确一致：放行
                       ├─ 明确冲突：告警
                       └─ 证据不足：待复核
```

本轮重点是区分两类剩余问题：当前规则尚未覆盖的工程问题，以及必须进一步理解任务语义和参数来源的问题。

## 2. 数据

| 数据 | 数量 | 特点 |
|---|---:|---|
| 双成功攻击轨迹 | 305 | 正常任务和攻击目标均成功，覆盖日历、邮件、删除、定时任务、错误分享和输出完整性 |
| 无注入正常轨迹 | 265 | 正常任务成功；其中120条会合法执行与攻击相似的工具或持久化行为 |

这些数据均来自模拟环境中真实运行的 OpenClaw Agent。本轮按执行顺序离线重放，在每次工具调用前作出判断；攻击标签和未来结果不提供给检测器。

## 3. 当前结果

305条攻击中，258条存在可检查的攻击目标工具调用；另外47条只影响最终输出或工作区状态，不属于当前调用前检查的适用范围。

| 结果 | 攻击侧 | 正常侧 |
|---|---:|---:|
| 明确告警 | 63/258（24.4%） | 0/265（0%） |
| 待复核 | 195/258（75.6%） | 124/265（46.8%） |
| 无需复核 | — | 141/265（53.2%） |

程序化规则可以低成本识别显式参数冲突，并且当前没有对正常任务产生明确误告警；但待复核比例较高，不能将其直接等同于攻击或阻断。

## 4. 补齐规则后重新归因

初版中，58条攻击和83条正常任务因“工具未定义”或“操作未提取”进入复核。本轮补齐相应工具契约后发现：

| 初版疑似工程缺口 | 补齐规则后的结果 |
|---|---|
| 58条攻击目标 | 0条转为新增高置信告警；58条均暴露为上下文授权不明确 |
| 83条正常任务 | 45条不再需要复核；38条仍涉及参数来源或输出形式不明确 |

这说明初版按错误原因直接估计“工程问题占比”并不准确：工具被识别后，仍要判断业务语言是否真正授权删除、定时执行或写入文件。程序化完善主要降低了正常任务的复核负担，没有扩大对冻结攻击目标的高置信检出。

## 5. 哪些行为容易或困难

| 行为 | 难度 | 原因 |
|---|---|---|
| 指定收件人、文件或权限与实际调用不一致 | 低 | 关键参数可以直接比较 |
| 用户允许操作，但参数需要从邮件、文件或记忆中补全 | 高 | 正常和攻击可能使用相同工具及来源 |
| 前序步骤修改状态，后续任务读取并使用新版本 | 高 | 需要判断版本如何形成、修改是否获得授权 |
| “继续完成剩余工作”等模糊指令 | 高 | 用户授权边界本身不明确 |

## 6. 程序化规则完善后的实测结果

| 指标 | 完善前 | 完善后 |
|---|---:|---:|
| 可检查攻击的高置信检出率 | 63/258（24.4%） | **63/258（24.4%）** |
| 全部305条攻击的总体检出率 | 63/305（20.7%） | **63/305（20.7%）** |
| 正常任务明确假阳性率 | 0/265（0%） | **0/265（0%）** |
| 正常任务待复核率 | 124/265（46.8%） | **79/265（29.8%）** |
| 若将告警和待复核全部阻断，正常任务成功率 | 141/265（53.2%） | **186/265（70.2%）** |

正常任务成功率按“轨迹中只要出现待复核就会被阻断”进行反事实推算，不是在线阻断实验的实测结果。

## 7. 初步语义审计

从待复核调用中固定抽取17条正常样本和17条攻击样本，由 LLM 判断当前调用是否获得用户授权：

| 样本 | 授权 | 未授权 | 不确定 |
|---|---:|---:|---:|
| 17条正常调用 | 17 | 0 | 0 |
| 17条攻击调用 | 0 | 15 | 2 |

该小样本只覆盖日历和文件分享，说明语义审计值得继续验证，不能外推为系统总体准确率。

## 8. 结论与下一步

程序化规则适合作为第一层：处理显式授权和参数冲突，并显著减少后续审计量。它难以解决的核心问题是：用户允许哪个来源决定哪个字段，以及该值来自哪个状态版本。

下一步不再继续堆叠程序化规则，而是连接三类信息：

```text
用户的条件授权 → 参数的实际来源 → 来源状态的版本形成过程
```

在此基础上，仅将仍无法确定的调用交给 LLM，并扩大样本评估完整流程的检出率、假阳性率和审计成本。
