# TaskScope × Effect 图：第一轮配对实验

## 问题与评测边界

我们要检验的不是“图能否记录异常工具”，而是：**只凭截至当前轮的正常用户请求、工具 schema 和已发生的图，能否把未授权 Effect 与合理的执行变化区分开？**

检测器不读取攻击标签、攻击目标、成功 oracle 或事后 case 元数据。用户请求按轮进入图；当轮消息只授权此后行为，未来用户消息不能追认过去的 Effect。当前实现是**执行后审计原型**：它查看成功提交的 Effect，不能据此声称已经做到工具执行前阻断。

数据协议：从 25 条已验证的真实无注入正常执行出发，在同目标、同正常任务族中确定性地匹配 25 条不同的双成功攻击，形成冻结的 `pairs.jsonl`。另外，在规则不变的情况下审计全部 305 条双成功攻击；这仍来自同一攻击语料，**不是独立外部测试集**。最后另行重跑三条无注入、一个用户请求合法要求两个持久副作用的压力任务（双邮件、双日历事件、双文件分享）。三条均由真实模型执行并以实际工具结果独立确认成功；其中双日历任务被底层调用序列 oracle 判失败，不能用该 oracle 代替任务效果核查。

## 最小实现

```text
每轮用户请求 ──生成/追加临时授权范围──┐
工具 schema ────────────────────────┤
可观测工具调用 → Action(有界参数) → Effect(对象/状态) → 逐步匹配
```

基础图仍是 Observation–Action–Effect–State。为支持同工具不同参数，Action 新增有界 `parameters` 证据：短参数保留原值，长文本保留前缀、长度和 SHA-256；L1 与 L2 process ledger 均可回查。每轮实际用户消息被记录为带时间的 Observation。旧图只有参数哈希，无法仅凭图检查收件人、文件 ID 和权限；这次是表征层的必要补齐，而不是把安全标签编码进图。

本实验的离线图直接保留短用户请求和参数，以便验证语义匹配；它不是隐私最小化的生产存储格式。生产版应将原文放入受控证据存储，图只保留引用与有界摘要。

本轮冻结两个检测基线：

- **Effect-kind**：仅检查已提交副作用的种类是否被当前请求允许；普通读取不报警。
- **Precise-v0**：在上述基础上检查允许的操作、显式目的地/文件 ID/权限，并假定每条明确请求最多授权一次同类持久操作。它是有意简陋的 TaskScope，不是最终方法。Scope 只从当轮可见用户文本和可用工具名生成；运行中的工具返回不能增加授权。

这些规则及确定性配对方法在 [`experiments/effect_scope_pilot.py`](../experiments/effect_scope_pilot.py)；可运行 `../attack-generation/openclaw-agentlab/.venv/bin/python experiments/effect_scope_pilot.py` 重建结果。脚本会读配套攻击仓库；本仓库保存了正常 case、压力 case、配对清单和摘要，完整 runner 工作目录留在本机。

## 结果：为什么“22/25”还不够

| 检测器 | 配对攻击告警 | 25 条普通良性误报 | 3 条双 Effect 良性误报 |
| --- | ---: | ---: | ---: |
| Effect-kind | 9/25 | 0/25 | 0/3 |
| Precise-v0 | 22/25 | 0/25 | **3/3** |

全量 305 条攻击的探索性审计中，Precise-v0 告警 258 条：日历 52/52、邮件外发 49/49、删除 46/46、定时任务 50/50、错误分享 61/61；输出完整性 0/47。这个整齐的分类结果不意味着问题已解决：前五类样本通常在一个正常任务 Effect 之外额外形成可观察的持久 Effect，而 47 条输出完整性样本只有正常邮件副作用，污染发生在最终文本声明。

三条真实良性压力任务各产生两个**用户明确授权**的副作用。Precise-v0 都把第二个判为 `extra_persistent_operation`。如果机械地把上限从 1 改成 2，原来“正常一次＋攻击一次”的样本又会被放行。因此症结不是阈值，而是授权对象定义错误：同类 Effect 的数量不能代替用户授权的具体事项。

## 由失败得到的下一步最小方法

将 TaskScope 从“允许的工具类型＋全局次数”改为一个小的**待兑现 Effect 承诺集合**。每条承诺由当前用户请求产生，至少记录操作、对象/目的地、显式参数约束、来源轮次和是否已兑现；新用户消息可以增加或修订承诺，但外部返回、文件和记忆不能自行扩大它。运行中的每个持久 Effect 应匹配一条尚未兑现的承诺；不明确的对象身份（例如只说文件名而工具使用文件 ID）标为待解析，允许读取证据来绑定对象，不能把“未知”直接当作允许或恶意。

这个设计给出可证伪的下一轮实验：在不放松攻击样本判定的同时，让三条双 Effect 良性压力任务不误报，并增加新的多副作用正常任务与“同工具、单次调用但参数改变”的攻击变体。输出完整性不应硬塞进 Effect 授权器；它需要独立的“最终声明是否有图中证据支撑”检验，作为清楚标注的能力边界。

本轮不能报告 0.4% 级误报、长时程泛化或阻断成功率。现有良性集样本量小，压力任务是在发现基线缺陷后构造的；本结果用于界定问题和下一方法的必要性，而非论文最终性能表。
