# 过程与内容统一表征：首轮验证

本轮完成的是表征规范和可运行的抽取接口，尚未完成全部过程采集或可靠的语义压缩。统一设计见 [图表征规范](../docs/REPRESENTATION_SPEC.md)。

## 改动及意义

保留 Observation、Action、Effect、State 四类节点。所有边增加同一套证据属性，区分直接观测、回执报告、契约声明和推断。来源关联、Effect 分类、对象版本匹配因此不再被默认解释成已证实因果。

启用内容实验时，Observation 正文与 Action 参数进入共享内容索引，用完整 SHA-256 去重，图上只存引用。语义抽取发生在采集之后，以“事实/要求/约束 + 主体/关系/对象 + 否定/条件 + 原文位置”为单位；预算不足时舍弃整条并报告数量。

## 内容抽取：看失败比看压缩数字更有用

六段正常文本：四个人工构造的压力片段，加上本次真实运行采集的两条用户输入。一次抽取后，以相同模型输出比较 512、2,048、4,096 B 三档预算。API 返回模型名为 `deepseek-v4-flash`；六次抽取共 9.204 秒。这只是单次、小样本的耗时记录。

| 样例 | 2,048 B 预算下实际大小 | 原文与抽取结果的检查 |
|---|---:|---|
| 报告只起草、禁止发送 | 450 B | 模型输出未定义的 `prohibition` 类型，禁止发送的命题被校验拒绝 |
| 审批后发送、含姓名则留草稿 | 983 B | 审批与替代路径被保留；禁止附带原始名单同样因类型错误被拒绝 |
| 撤回旧请求、改为保存草稿 | 1,274 B | 引用都可定位，但旧发送请求没有被明确标为失效；撤回被表示成另一个普通请求 |
| 约 13 KB 文档尾部限制 | 706 B | 找到两条尾部限制；规范化命题未充分保留 `only` 和 workspace 限定。重复背景句因引用位置不唯一被拒绝 |
| 真实任务：查询并总结 | 1,576 B | 规范化命题保留了三项禁止行为，但部分引用仅为 `edit files` 等短语，未包含支配它们的否定词 |
| 真实任务：写入 MEMORY.md | 768 B | 写入对象、内容要求与不得调用其他工具均保留；主体字段仍混用了发话者与执行者 |

2,048 B 与 4,096 B 的保留结果相同：这些错误主要来自抽取和语义定义，不是空间不足。512 B 下多个完整命题被省略，进一步说明固定小预算不能保证信息覆盖。

脚本还记录“预标注完整子句是否被某条引用包含”。该指标只有 8/13，但它既会漏算跨片段覆盖，也不能证明命题语义正确，因此不是语义准确率。表中的判断来自对本轮原文与模型输出的逐项人工式检查，尚无独立双人标注。

## 对设计的决定

1. **证据与解释分离。** 过程关系和内容命题都标出依据。通过格式校验或引用校验，不能升级成“语义已验证”。
2. **先明确命题的语义范围。** 一个内容单元需要连同支配它的否定、条件和修订语境核查；仅提取动作三元组不够。主体统一指执行者还是发话者，也必须在规范中定义后再评测，不能让下游自行猜测。
3. **以可回答的问题驱动压缩。** 下一轮固定“可否发送、给谁、何时、哪些要求已失效”等问题，比较原文与摘要的回答及证据。保持图结构不变，先验证抽取规范和内容保留策略，而非增加攻击类别规则。

首轮已经说明接口能运行，也明确暴露了信息损失；不能据此声称复杂意图压缩问题已解决。多源依赖、真实副作用验证、State 内容快照和全局运行时内容预算仍是未完成项。
