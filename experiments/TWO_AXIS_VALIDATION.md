# 图能表达什么：过程与内容的真实执行验证

本轮先验证两件事：图是否准确记录观测范围内的执行；内容压缩后是否还能回答任务的关键问题。没有加入攻击分类或防御决策。

## 实验如何执行

沿用攻击仓库的 `VictimAgent` 和 DeepSeek API，让模型自主选择工具。工具替换为真实本地文件读、写和列表操作，文件放在每次运行新建的隔离目录。没有预先指定工具调用轨迹，也不是成功路径回放。环境仍是 AgentLAB 驱动器，尚非已安装的原生 OpenClaw 全栈。

每次五个用户轮次：

```text
读长政策文档和数据 → 写报告草稿
修改接收人与审批要求 → 写 MEMORY.md
清空模型上下文 → 读 MEMORY.md 和草稿，报告当前要求
读取不存在的文件 → 恢复并写 status.txt
再次写入同样内容 → 检查是否虚增状态版本
```

政策文档包含重复背景段落和尾部业务条件。任务、文档与答案是可控构造的；执行过程是模型实际生成的。这是小规模功能实验，不是自然任务分布上的统计评测。

## 过程：用独立执行记录逐项匹配

对照记录直接保存模型输入的消息与工具 schema、可见响应、工具请求/结果和调用前后的磁盘 SHA-256 快照。评估按调用 ID、实际参数、对象、状态及版本关系匹配，不使用图节点数量作为正确性的依据。消息与 schema 通过内容引用回查；因此参数/上下文保真是“图 + 证据索引”的能力，不能说小图本身包含了全部内容。这里未验证网络请求的全部字段或模型内部执行。

| 运行 | 用户轮次 / 模型调用 | 工具动作、参数、状态与返回匹配 | 文件内容变化：正确 / 图中记录 / 磁盘实际 | 跨会话读取关系 |
|---|---:|---:|---:|---:|
| 回执版 1 | 5 / 14 | 12/12 | 3 / 4 / 3 | 2/2 |
| 回执版 2 | 5 / 15 | 13/13 | 3 / 4 / 3 | 2/2 |
| 快照版 | 5 / 13 | 10/10 | 3 / 3 / 3 | 2/2 |

三次运行的模型输入输出均逐项匹配。每次都有一次真实缺失文件读取失败和一次重复写入；新上下文通过真实文件读取恢复了此前的记忆。三次均生成草稿和记忆，生产配置保持不变，status.txt 最终内容正确。这里只验证这些具体结果，不给完整任务质量打分。

发现并修正：成功写入不一定改变内容。回执版把相同内容的再次写入多记为一个版本，按“文件内容变化”定义，状态精确率为 3/4。现在操作和成功 Effect 仍保留，但仅在前后内容指纹不同时生成 State。读取时同时核对对象与指纹，指纹不符则不连接到旧版本。

这不是新增一种行为节点，而是明确 State 的语义。没有快照的适配器仍保留 reported 证据，不能自动获得同样保证。独立真实运行的轨迹有差异；同序列单测另外验证了重复写入的差别、外部改动导致版本不匹配，以及删除记录后评估器确实能发现遗漏。

State 目前从写入后的变化开始建版本；初始就存在且从未修改的文件，通过读取 Observation 和原文引用表达，尚未全部物化为初始 State 节点。

## 内容：先保留关键原文，再评估理解

初步实现为“按段落分块 → 长内容由 LLM 选段落 ID → 原样保留片段、来源和顺序”。短内容完整保留；单份结构化摘要预算为 2,048 B，超预算整段省略并标记。原文仍可回查。这样避免命题改写造成的主体、否定和撤回失真，但选择遗漏仍可能发生。

用图中实际采集的用户输入和工具返回构成内容视图；选择器看不到测试问题与答案。预先确定八个问题，覆盖当前接收人、审批、政策阈值、日期、配置边界、禁止内容、某轮权限和失败恢复要求。分别让同一个 reader 读取原文、前缀截断和抽取式视图，再与预设答案比较。

| 运行 | 原文视图：字节 / 正确问题 | 截断视图：字节 / 正确问题 | 抽取式视图：字节 / 正确问题 |
|---|---:|---:|---:|
| 回执版 1 | 21,790 / 8/8 | 7,279 / 8/8 | 5,808 / 8/8 |
| 回执版 2 | 21,981 / 8/8 | 7,488 / 7/8 | 6,017 / 8/8 |
| 快照版 | 21,022 / 8/8 | 6,475 / 7/8 | 5,008 / 8/8 |

截断在后两次运行丢失了政策中“审批后仅可修改 staging.yaml”的信息；第一次未丢，是因为 Agent 草稿再次写出了这个条件。这说明评估必须考虑真实执行中的信息重复，不能仅用一个长文本样例推断所有任务。

以上是来源视图的 UTF-8 JSON 大小，包含事件标签，不是完整图大小。两种压缩使用相同单份预算上限，但没有强行填满相同总字节。reader 根据选项作答，仍有猜测和模型偏差；引用 ID 有效也不等于语义支持已核验。三条受控轨迹的 8/8 不能当作大规模语义保真率或检测率。

## 当前可以说到哪一步

| 维度 | 已有证据 | 尚无保证 |
|---|---|---|
| 过程事件 | 本实验中的模型边界、顺序工具调用、失败与恢复可追踪 | 并发、流式工具、原生 OpenClaw 完整生命周期 |
| 状态变化 | 本地文件内容变化及再次读取可核验 | 权限/时间戳、数据库、外部 API、副作用的通用验证 |
| 来源关系 | 能记录哪些上下文进入了产生该动作的模型调用 | 模型实际用了哪段信息、真实因果关系 |
| 内容含义 | 本轮的事实、否定、条件和修订可在片段视图中读出 | 跨段指代、隐含意图、单段超长文本、未被选择的信息 |
| 规模 | 本轮内容视图约缩小到原来的 24%–27% | 150 轮全局预算、检索和回查成本、总存储有界 |

快照版完整图为 41,310 B，独立内容索引为 154,185 B，原始对照记录为 159,840 B；这些文件用途不同且存在重复，不能把内容视图的 5,008 B 当作总成本。当前保存完整模型输入以核验采集，会重复存储增长的历史上下文。

下一步以同一套协议扩展正常任务：先加入跨段修订和多文件依赖，再拉长真实用户轮次；分别检查内容遗漏、版本关系错误和预算增长。暂不增加攻击类别规则。

## 代码与复现

核心：[过程采集](../src/greatwallguard/agentlab_recorder.py)、[状态版本](../src/greatwallguard/graph.py)、[抽取式内容压缩](../src/greatwallguard/extractive.py)。[真实文件工具与独立评估](real_process_support.py)不使用图计数生成参考答案。

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY PYTHONPATH=src \
  ../attack-generation/openclaw-agentlab/.venv/bin/python \
  experiments/run_two_axis_validation.py --state-evidence snapshot \
  --output-root experiments/two_axis_v1/new_run
```

`--state-evidence receipt` 可复现只按回执记版本的对照。已有结果目录不会被运行脚本覆盖；语义部分可用 `--content-only` 重新测量，但会覆盖该目录的内容评测文件。

结果：[回执版 1](two_axis_v1/run01/process_metrics.json)、[回执版 2](two_axis_v1/run02/process_metrics.json)、[快照版过程](two_axis_v1/snapshot01/process_metrics.json)、[快照版内容](two_axis_v1/snapshot01/content_metrics.json)。各目录另有原始调用记录、完整图、内容证据和真实任务文件。旧回执版结果生成于快照选项加入之前，因此其中没有 state_evidence 字段。

30 项单元测试通过，包括刻意破坏记录验证评估器能检错的测试；真实 API 结果独立落盘，未用单元测试替代。
